# KS-019 販売状態とCTA文言を一つの判定へ統一

判定: **検証完了・本文変更不要 (構造上の不一致 0 件)。再発防止テストを追加** / 実施: 2026-09-15 / バッチ B

## 現行の仕組み (描画器 `python/raos/application/editorial/purchase_support.py`)

- 販売条件パネル `.ps-seller[data-ps-offer][data-ps-state][data-ps-price-state]` は offer ごとに 1 回描画され、`eligible_link(o)` が偽 (型番未照合・売り切れ・案内保留・価格失効等) なら購入ボタンの代わりに `.ps-unavailable` の文言 (「確認時は売り切れでした…」「販売条件の確認が完了していないため…案内を保留しています」) を出す。
- 購入ボタン `a.ps-offer-link[data-raos-offer-id][data-raos-placement]` は `cta()` が同じ offer 判定から生成し、placement は `top_summary` / `comparison_table` / `product_card` / `final_summary` の 4 種。`listing_reference` (「楽天で見る」「販売先で見る」) は在庫確認用の遷移で、購入推奨ではない。
- 型番不一致 (`identity_verified` が真でない) は `cta()` が `PURCHASE_CTA_INELIGIBLE` で停止し、生成自体が失敗する。
