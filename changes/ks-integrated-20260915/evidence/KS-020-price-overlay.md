# KS-020 / バッチG — 楽天価格の再取得についてのオーナー決定 (2026-09-16)

## 決定

1. **WordPress のデータベースに残る hash を許容する** (2026-09-16、オーナー回答「残ってよい」)。
   - 価格を消した後も、注入した本文とテーマの sha256 が、plugin の proposal 行の `before_sha256` / `after_sha256` 列と undo 用の設定に残る。
   - hash は価格そのものではないが、価格の候補を総当たりで当てはめれば一致を確かめられる。
   - この決定により、契約 §10.1-3 の「残る作業 4 (OWNER DECISION REQUIRED)」は解消する。行や設定を消す処理は作らない。
   - 契約本文への反映は、バッチG の branch (`claude/ks-g-integration-20260916`) で行う。
2. **plugin の配置は、オーナーと一緒に行う** (2026-09-16、オーナー回答「いまから一緒にやる」)。
   - 手順: (1) 配布物を作り `runtime-manifest.v1.json` の `plugin.file_manifest_sha256` と照合 → (2) Claude が本番に変更案を登録 → (3) オーナーが wp-admin の「RAOS Codex proposals」で承認 (15 分・1 回きりの適用許可が出る) → (4) Claude が適用し、状態を確認。
   - 本番の状態 (2026-09-16 09:00 JST 読み取り): WordPress 7.1、PHP 8.3.32、plugin runtime revision `3959d130…`、テーマ `kurashinoshirube-child` 1.6.0。適用は既定で不許可、承認時だけ 15 分の 1 回きり。

## 価格を本番に出す前に、まだ残っていること

1. plugin の配置 (上の 2)。配置後、本番の plugin ファイルが `plugin.file_manifest_sha256` と一致することを確かめる。
2. purge 公開の後に、WordPress の投稿リビジョン (`post_type=revision`) とページキャッシュ・CDN に、価格入りの本文が残るかを実測する。残るなら、同じ期限内に消す手順を用意する。
3. preview 用のローカル WordPress (docker のデータベース) に取り込まれた価格入り本文の後始末の手順を決める。
4. 配信中に本番へ届く経路をすべて塞ぐ作業 (バッチG の各ラウンド)。第6ラウンドで、設定・起動の仕組みとコードの両方から経路を洗い出している。

## 決めていないこと (オーナー判断が残る)

- 別の run が配信中のときに、run を指定した prepare を拒否するか (契約 §10.1-11)。
- 販売元が複数 SKU をまとめている offer (`multi_sku=false`) を、編集者が 1 つの型番と確かめる運用 (§10.1-6)。
- 楽天 API の取得件数を 2 件にするか (§10.1-8)。
