## Execution and data boundary

The generator performs deterministic local reads, strict validation, hashing,
JSON/YAML rendering, no-write comparison, and a locked, recoverable,
all-or-nothing transaction for the reference plan and manifest only. Staged,
previous, absent, and coordinator files use fixed private companion names;
the closed coordinator binds the exact ordered output inventory, parent
device/inode identities, original output tuples, and staged bytes and identities.
Targets, staged companions, physical ancestors, and the writer-lock parent are
revalidated immediately before commit and before coordinator cleanup. File and
parent-directory changes are fsynced, and rollback restores the prior bytes,
inode, mode, and mtime. A write run recovers a valid pending transaction before
reading sources. Missing or replaced transaction parents retain the coordinator
and fail closed. `--check` takes a shared lock and refuses any pending or
malformed transaction without mutation.

This local filesystem transaction is not a repository, database, queue, Job,
Event, provider, publication, staging, release, or Production operation. The
generator has no network, browser, clock, random, or external action and reads
no secret, credential, personal data, production data, Rakuten review body, or
live provider response.

The reference plan does not invoke ST-0504 or ST-1401. It does not apply the
candidate ST-1701 category-specific identity or freshness values. Synthetic
validator fixtures remain the only allowed future local data class, but this
slice creates no fixture.
