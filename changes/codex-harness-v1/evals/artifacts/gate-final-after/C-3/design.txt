# 公開記事の更新情報表示

## 目的と適用範囲

読者が記事の更新日時と鮮度を判断できるよう、既存の公開情報をそのまま表示する。
`python/raos/application/publishing/public_update_notice.py` に
`render_public_update_notice(projection) -> str` を追加する。成功条件は指定形式の表示、
必須値欠損時の `ValueError`、HTML エスケープ、公開／内部境界と既存契約の維持である。

判断の正本は [現行 architecture](../docs/architecture/current-system.md)、
[integration baseline §5.1–5.2](../docs/canonical/01_integration/RAOS_07_integration_design_v1.0.md)、
[公開 projection の実装](../python/raos/domain/publishing/public_projection_v2.py)、
[ST-0904 V2 contract](../changes/st-0904/contracts/public-projection-runtime.v2.yaml)、
[Public OpenAPI](../contracts/raos-v0.4/contracts/openapi-public.v0.1.yaml) とする。
ST-0904 の旧 reference plan に記載された未実装状態や承認手順を、現行の局所実装へ適用しない。

## 採用したデータ経路と理由

承認済みの不変 Publication Snapshot → 既存 projector → public projection →
この表示関数、という公開側の経路を維持する。関数の入力は既存の projection mapping であり、
参照するのは `projection["article"]["updated_public_at"]` と
`projection["article"]["freshness_status"]` だけである。承認・投影の検証は既存の上流が所有し、
この関数は公開権限を付与しない。

内部 Evidence を直接読んで更新日や鮮度を再計算する案は、承認済み snapshot と表示の整合を
失わせ、Public Web が内部 repository に到達する経路を作るため採用しない。
Finance の直接参照も、表示に必要な情報ではなく、内部財務の漏出や編集判断との混同を招くため
採用しない。内部値を新しい projection フィールドに移す案も、既存の2項目で要件を満たせるため
不要である。追加する依存は標準ライブラリの `Mapping` と `html.escape` のみとし、I/O は行わない。

## 表示と欠損の扱い

- 返り値は `更新: <article.updated_public_at> / 状態: <article.freshness_status>`。
  両値に `html.escape(..., quote=True)` を適用し、タグ、`&`、一重・二重引用符をエスケープする。
- 入力／`article` が mapping でない場合、またはどちらかの値が未指定、`None`、空文字、
  空白のみ、文字列以外の場合は `ValueError`。例外に入力値を含めない。
- 日時の変換、状態の再評価・翻訳・列挙型追加は行わない。`UNKNOWN` は有効な文字列として表示する。
  エスケープ以外は元の値を保ち、入力を変更しない。
- `updated_public_at` は既存 OpenAPI で省略・null が許される。この関数の表示前提として必須とし、
  OpenAPI 全体の必須項目には変更しない。既存の recorded projection は更新日時が `None` なので
  関数は `ValueError` を送出する。`published_at`、現在時刻、内部データで補完しない。

## 隣接影響と非対象

- Snapshot／projector：allowlist、redaction、hash、承認・idempotency、`UNKNOWN` の安全な既定値を維持。
  合成 fixture の更新日時は回帰テスト内のコピーにだけ設定し、生成物と generator 入力は変更しない。
- 公開 API／Web／WordPress：schema、生成型、projection のフィールド追加や既存表示への組込みはない。
  呼出し側は公開済み projection を渡し、更新日時がない場合の `ValueError` を扱う必要がある。
  この関数は本文や広告表示を置き換えず、CTA、disclosure、auth/authz、publication、kill switch に
  作用しない。上流の承認・公開境界の代わりになる検証器ではない。
- Evidence／Finance／raw AI：import、repository、port、adapter の接続を追加しない。
  余分な入力値を出力へ混ぜず、欠損時にも内部値へ fallback しない。
- 外部作用：ネットワーク、DB 書込み、CMS 操作、staging、公開、release、Production 反映は伴わない。
  不可逆操作はなく、表示関数・回帰テスト・設計記録に限定した変更である。

## 検証

回帰テストは既存形式の合成 projection を使い、表示、入力非変更、両値の HTML エスケープ、
欠損・不正値の `ValueError`、`UNKNOWN` の保持、内部値の非表示・fallback 禁止を確認する。
既存 static boundary のネットワーク・DB・CMS import 禁止の対象に表示関数を追加する。

実行範囲はユーザー指定に従い、次の3ファイルのみとする。

```sh
.venv/bin/python -m pytest -p xdist.plugin -n 2 -q \
  tests/st0904_v2/test_public_update_notice.py \
  tests/st0904_v2/test_domain.py \
  tests/st0904_v2/test_static_boundary.py
```

実行結果：**41 passed in 1.86s**。追加回帰29件、既存 domain 8件、static boundary 4件が成功した。
これは隔離環境内の合成データによる検証結果であり、live 公開の検証を意味しない。
ネットワーク・保存済み checkout を必要とする検査と全件 CI は依頼範囲外のため未実行。
