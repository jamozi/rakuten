# 公開記事の更新情報表示

## 採用したデータ経路

`Publication Snapshot (ST-0903) → Public projection (ST-0904) →
render_public_update_notice(projection) → HTML エスケープ済み表示文字列`。
関数に渡すのは既存の `PublicProjectionResultV2.projection()` と同じ辞書形式で、
`article.updated_public_at` と `article.freshness_status` だけを参照する。
関数自身は Snapshot や内部サービスを読み出さず、標準ライブラリだけを使用する。

表示は `更新: <updated_public_at> / 状態: <freshness_status>` とする。
両方の値を `html.escape(..., quote=True)` で処理し、タグ、アンパサンド、
引用符を HTML として解釈させない。日時の再整形や状態の翻訳・再判定はしない。
入力を変更せず、追加の HTML 要素や公開フィールドも生成しない。

## 判断の根拠と不採用案

- `docs/canonical/01_integration/RAOS_07_integration_design_v1.0.md:73` は
  Public Web の参照先を Public Read Model に限定し、Editorial、Evidence、Finance、
  AI Raw Artifact への到達を禁止している。
- `contracts/raos-v0.4/contracts/openapi-public.v0.1.yaml` の
  `PublicArticleDocument` と
  `python/raos/domain/publishing/public_projection_v2.py` の
  `PUBLIC_ARTICLE_FIELDS` に必要な2項目が既にある。公開契約の追加は不要。
- Evidence の観測日時や内部状態から直接補完する案は、公開更新日時と内部の観測日時を
  混同し、公開境界を迂回するため不採用。Finance への直接参照も表示に不要であり、
  財務データを公開処理へ持ち込む依存と権限を増やすため不採用とする。

## 必須値と隣接影響

- projection / article が Mapping でない場合、article が欠ける場合、または2項目の
  いずれかが欠落、`None`、空文字、空白のみ、文字列以外の場合は `ValueError`。
  例外には入力値を含めない。他の公開フィールドの妥当性検証は既存 projector の責務。
- OpenAPI では `updated_public_at` は任意かつ nullable であり、現在の recorded projector
  も `updated_public_at=None`、`freshness_status="UNKNOWN"` を出力する。
  この既存出力に関数を適用すると `ValueError` になる。表示関数の前提として値を要求し、
  公開契約全体の必須条件は変更しない。`published_at`、現在時刻、内部値からは補完しない。
- 呼び出し側は公開 projection の必須値が揃った時に利用する。`UNKNOWN` など既存の状態値は
  そのまま表示する。この追加では projector、Snapshot、OpenAPI、allowlist、DB role / grant、
  Freshness の判定処理、Evidence / Finance の interface を変更しない。
- disclosure、public/internal isolation、publication / kill-switch gate は既存処理に維持する。
  API route、WordPress の記事・テーマ・プラグインへの組み込み、DB / CMS 書込みは行わない。
  canonical / upstream / generated fixture とその content hash は変更しない。
- 回帰テストは既存 recorded projection のメモリ上のコピーに合成日時を設定する。
  内部名を持つ合成の余分な項目は、表示や補完に使われないことを検証するためだけに渡す。
  それらを正式な公開フィールドとして許可する変更ではない。
