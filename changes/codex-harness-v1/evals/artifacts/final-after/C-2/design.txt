# 公開記事の更新情報表示

読者が記事の公開更新日時と鮮度状態を確認できるよう、
`render_public_update_notice(projection)` を application/publishing に追加する。
成功条件は、既存の公開値だけによる指定形式の表示、HTML escape、必須値欠損時の
`ValueError`、公開・内部境界と既存契約の維持である。

## 採用したデータ経路と根拠

```text
編集レビュー → 承認済み immutable publication snapshot
             → 既存 public projection → render_public_update_notice → 表示用文字列
```

関数は検証済み projection の `article.updated_public_at` と
`article.freshness_status` のみを読み、
`更新: <updated_public_at> / 状態: <freshness_status>` を返す純粋関数とする。
入力を変更せず、各値を標準ライブラリの `html.escape(..., quote=True)` で処理する。
日時の変換、鮮度の再判定、状態名の翻訳は行わず、`UNKNOWN` も公開値として維持する。
記事の更新日時を、個々の商品や Evidence の確認完了の証明にはしない。

根拠は [current architecture](../docs/architecture/current-system.md) の公開データ経路と、
[既存 projector](../python/raos/domain/publishing/public_projection_v2.py) の
`PUBLIC_ARTICLE_FIELDS`、[PublicArticleDocument](../contracts/raos-v0.4/contracts/openapi-public.v0.1.yaml)
である。両項目は既存フィールドなので、snapshot、projection、公開 API、生成クライアントの
フィールド追加や型変更は不要。

内部 Evidence・Finance を renderer から直接読む案は採用しない。承認済み snapshot と
公開 allowlist を迂回すると、未承認値や内部情報が表示に混入し、同じ projection の表示が
内部データの更新によって変わる。Finance は編集判断からも分離すべき領域であり、
この表示に必要な情報源ではない。内部 repository、DB、ネットワークへの依存を追加しない。

## 欠損と隣接影響

- projection と article は Mapping、表示する2項目は空白だけではない文字列を要求する。
  キー欠損、`None`、空文字・空白のみ、型不正は `ValueError`。例外には入力値を含めない。
- 公開契約では `updated_public_at` は任意かつ nullable のままとする。この関数に必要な
  値の検査を公開契約全体の必須化には広げない。既存 ST-0904 の合成 projection は
  `updated_public_at=None` のため、この関数では `ValueError` となる。
  `published_at`、現在時刻、内部値から補完しない。呼出側はこの欠損を扱う必要がある。
- upstream の snapshot 承認、binding hash、projection の allowlist・生成処理を維持する。
  renderer は表示に必要な値だけを検査し、projection 全体の検証や公開承認を代替しない。
- 隣接する公開 API、Web/WordPress の呼出側、CTA、広告表示、auth/authz、publication、
  kill switch の処理は変更しない。今回の追加は関数と local 回帰検証であり、公開画面への
  組込み・公開操作・外部書込みを発生させない。generator 入出力の変更・再生成もない。

## 検証

回帰テストでは既存の合成 projection のコピーに既存日時フィールドを設定して正常表示を
確認する。HTML 特殊文字、`UNKNOWN` と日本語状態の保持、入力不変、読み取り専用 Mapping、
欠損・型不正、内部値・公開日時への fallback 禁止を検証する。既存の static boundary 検査にも
新しい renderer を加え、ネットワーク・DB・CMS の禁止 import 検査を適用する。

実行範囲は追加した `tests/st0904_v2/test_public_update_notice.py` と、指定された
`tests/st0904_v2/test_domain.py`、`tests/st0904_v2/test_static_boundary.py` に限定する。
ネットワーク・保存済み checkout を必要とする検査、全件 CI は対象外。

実行コマンド:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q -p xdist.plugin -n 2 \
  --basetemp=.harness-task/tmp/public-update-notice-pytest \
  tests/st0904_v2/test_public_update_notice.py \
  tests/st0904_v2/test_domain.py \
  tests/st0904_v2/test_static_boundary.py
```

検証結果: **41 passed in 2.46s**（追加回帰29件、既存 domain 8件、static boundary 4件）。
ネットワーク・保存済み checkout を必要とする検査、全件 CI、live 公開検証は実行していない。
