# 公開記事の更新情報表示

## 目的と採用経路

読者が公開記事の更新日時と鮮度状態を確認できるよう、
`python/raos/application/publishing/public_update_notice.py` に
`render_public_update_notice(projection) -> str` を追加する。
成功条件は指定文言、HTML escape、必須値欠損時の `ValueError`、公開・内部境界の維持。

採用経路は **承認済み immutable publication snapshot → 既存 public projection →
表示関数 → 呼出側の表示**。関数が読む値は `projection["article"]` 内の
`updated_public_at` と `freshness_status` だけで、渡された projection を変更しない。
snapshot の承認・整合性検証と public projection の生成は既存の上流境界が所有する。
この表示関数は公開認可を判定・付与しない。

根拠は [current architecture](../docs/architecture/current-system.md) の公開データ経路、
[projection domain](../python/raos/domain/publishing/public_projection_v2.py) の
`PUBLIC_ARTICLE_FIELDS` と `PublicProjectionResultV2.projection()`、
[公開 OpenAPI](../contracts/raos-v0.4/contracts/openapi-public.v0.1.yaml) の
`PublicArticleDocument`。必要な2項目は既存契約にあり、契約・allowlist・生成物は拡張しない。

内部 Evidence への直接参照案は、承認済み内容と異なる最新の内部状態を表示するおそれがあり、
snapshot の再現性と公開・内部分離を損なうため採用しない。Finance への直接参照案も、
更新情報の表示に不要な財務情報への依存・漏出経路を作り、編集と財務の分離を損なうため採用しない。
内部 repository・DB・API・CMS・raw AI へ接続せず、既存の公開値を表示する純粋関数とする。

## 表示と欠損

- 出力は `更新: <article.updated_public_at> / 状態: <article.freshness_status>`。
  両値を `html.escape(..., quote=True)` で処理し、`& < > " '` を escape する。
- projection と article は mapping、2項目は空白だけではない文字列を要求する。
  コンテナ・キーの欠損、null、空文字、空白のみ、文字列以外は `ValueError`。
  エラーに入力値を埋め込まない。
- 日時の変換・鮮度の再判定は行わず、公開値をそのまま表示する。
  `UNKNOWN` / `UNAVAILABLE` を成功状態へ置換しない。
- `published_at`、現在時刻、別階層の値、内部 Evidence・Finance による補完は行わない。

## 隣接影響と範囲

公開 OpenAPI の `updated_public_at` は任意かつ nullable。
現行の recorded projector は `updated_public_at: null`、`freshness_status: UNKNOWN` を生成する。
その出力をそのまま本関数へ渡すと、要求どおり `ValueError` になる。
表示のために日時を捏造したり、snapshot・projector の既存動作や公開契約の必須指定を変えたりしない。
成功例の回帰テストでは、既存 projection のコピーの既存フィールドに synthetic な日時を設定する。
将来の呼出側は更新日時がない記事の表示方針を扱う必要がある。

API / Web / WordPress への組込み、公開・デプロイはこの関数追加の対象外。
auth/authz、CTA、disclosure、publication、idempotency、kill switch、用途別 default-off は
既存の所有箇所を維持する。入力を変更しないため、記事本文・ルート・他の公開値にも変更はない。
新規依存、永続化、ネットワークアクセス、不可逆操作はない。
既存の静的境界テストの対象に新関数を追加し、ネットワーク・DB・CMS import 禁止を引き継ぐ。

## 検証

ユーザー指定の隔離評価範囲に従い、次の3ファイルだけを実行する。
通常開発の `make fast`、依存取得を伴う setup、保存済み checkout に依存する検査、
ネットワーク検査、全件 CI は実行しない。

```sh
PYTHONDONTWRITEBYTECODE=1 TMPDIR="$PWD/.harness-task/tmp" .venv/bin/python -m pytest -q \
  -p xdist.plugin -n 2 \
  -m "not live and not external and not raos_owner_private and not database and not storage" \
  tests/st0904_v2/test_public_update_notice.py \
  tests/st0904_v2/test_domain.py \
  tests/st0904_v2/test_static_boundary.py
```

回帰対象は表示文言、UNKNOWN/UNAVAILABLE の保持、両項目の HTML escape、欠損・不正型、
入力非変更、無関係な synthetic 内部値の非表示、null 更新日時を他の値で補完しないこと。
既存 domain / static boundary テストで閉じた公開契約、内部値の除外、無権限・無作用を確認する。

実行結果: 上記コマンドで **42 passed in 1.97s**（exit code 0、失敗・skip なし）。
追加回帰テスト30件と、指定された既存2ファイルの12件が成功した。
この結果は local の指定範囲の検証であり、live 公開・全件 CI の検証結果ではない。
