# 公開記事の更新情報表示

読者が公開済みの記事の更新日時と鮮度状態を確認できるよう、
`python/raos/application/publishing/public_update_notice.py` に
`render_public_update_notice(projection) -> str` を追加する。

## 採用するデータ経路と理由

承認済みの不変 publication snapshot → 既存 public projection →
`article.updated_public_at` / `article.freshness_status` → HTMLエスケープ済み表示文字列、
という既存の公開経路を使う。表示は `更新: <日時> / 状態: <状態>` とする。
関数は渡された projection の2項目だけを読み、I/O・状態更新・承認判断を行わない。
snapshot の承認と projection の検証・取得は既存の上流境界の責務であり、
この関数に辞書を渡せることは公開権限や承認の証明にはならない。

内部 Evidence や Finance repository を表示時に直接読む案は採用しない。
承認 snapshot と異なる時点の内部値が公開される経路を作り、公開／内部の分離と
編集判断／財務の分離を崩すためである。内部値を projection に新設して渡す必要もない。
既存の公開2項目で要求を満たせるため、公開 allowlist・OpenAPI・生成済み型・snapshot
契約を増やさず、単純な表示変換として実装する。

根拠:

- `AGENTS.md` の Mission と公開／内部分離の不変条件。
- `docs/architecture/current-system.md` の Data flow and ownership。
- `docs/canonical/01_integration/RAOS_07_integration_design_v1.0.md` の
  Public Web は Public Read Model のみを参照する制約。
- `python/raos/domain/publishing/public_projection_v2.py` の
  `PUBLIC_ARTICLE_FIELDS` と `build_public_projection_v2`。
- `contracts/raos-v0.4/contracts/openapi-public.v0.1.yaml` の
  `PublicArticleDocument`。両項目は既存で、`updated_public_at` は省略・null を許容する。

## 欠損とHTMLの扱い

projection / article が mapping でない場合、または必須2項目が欠落・null・空文字・
空白のみ・文字列以外の場合は `ValueError` とする。例外文に入力値を含めない。
文字列は日時変換や状態の再判定をせず、そのまま `html.escape(..., quote=True)` に通す。
`UNKNOWN` / `UNAVAILABLE` もそのまま表示し、鮮度良好へ読み替えない。
公開日時・現在時刻・内部 Evidence / Finance から欠損を補完しない。

## 隣接影響と範囲

- 公開契約の nullable な更新日時を必須へ変更しない。必須条件は、この表示関数の
  正常な出力を作るための条件に限定する。現在の ST-0904 V2 のローカル候補は
  `updated_public_at=None` / `freshness_status=UNKNOWN` なので、そのまま渡すと
  `ValueError` になる。fixture や generator に更新日時を捏造して埋めない。
- snapshot、projection の生成・整合性検証と、公開 API / Web / WordPress の既存利用側は
  変更しない。今回の成果は表示関数であり、ページへの組み込みや公開反映は含めない。
  呼出側は、更新日時が利用可能な projection を渡す必要がある。
- 入力を変更せず、記事本文・広告表示・CTA・おすすめ順位・財務集計に影響を与えない。
  auth/authz、publication、idempotency、kill switch と default-off の権限境界も維持する。
- schema・migration・generator 入力に変更はなく、再生成や DB 変更は不要。

## 検証

回帰テストは既存の synthetic projection を使い、表示形式、両項目のHTMLエスケープ、
欠損／不正型の `ValueError`、UNKNOWN 等の維持、入力不変、公開日時や合成した内部値で
補完しないことを確認する。既存の静的境界検査にも新しい表示モジュールを追加する。

実行対象は追加した `tests/st0904_v2/test_public_update_notice.py` と、指定された
`tests/st0904_v2/test_domain.py`、`tests/st0904_v2/test_static_boundary.py` に限定する。
依存は配置済み環境を利用し、ネットワーク・保存済み checkout が必要な検査、
`make setup` / `make fast` と全件 CI は今回の明示された検査範囲に含めない。

実行コマンド（配置済み依存、作業ディレクトリ内の一時領域、通常テストの並列実行）:

```sh
PYTHONDONTWRITEBYTECODE=1 TMPDIR="$PWD/.harness-task/tmp" .venv/bin/python -m pytest -q \
  -p xdist.plugin -n 2 \
  -m "not live and not external and not raos_owner_private and not database and not storage" \
  tests/st0904_v2/test_public_update_notice.py \
  tests/st0904_v2/test_domain.py \
  tests/st0904_v2/test_static_boundary.py
```

実行結果: **42 passed in 2.08s**（回帰30件、既存domain 8件、静的境界4件）。
指定範囲の失敗・skip はない。範囲外の検査や live 公開の検証結果には拡張しない。
