# 公開記事の更新情報表示

## 採用したデータ経路

既存の ST-0903 publication snapshot → ST-0904
`build_public_projection_v2` → `PublicProjectionResultV2.projection()` が返す
public projection → `render_public_update_notice(projection)` とする。
表示関数が読む値は `article.updated_public_at` と
`article.freshness_status` の2項目だけであり、呼び出し側から既存の公開用 mapping を渡す。
新しい内部 source、port、adapter、DB 接続は追加しない。

両項目は既存の `PUBLIC_ARTICLE_FIELDS`
（`python/raos/domain/publishing/public_projection_v2.py`）および
`contracts/raos-v0.4/contracts/openapi-public.v0.1.yaml` の公開記事スキーマに存在する。
公開契約のフィールド、required、型、allowlist を変更する必要はない。

## 選定理由と検討した代案

内部 Evidence の観測日時・鮮度を直接参照する案では、公開更新の事実と内部観測の時点を
混同し、承認済み snapshot／公開 projection を経由しない依存が生まれる。
Finance への直接参照も更新表示の2項目には不要で、公開側への内部データ露出と
editorial／finance の分離を損なうため、どちらも採用しない。
内部値を公開 projection に追加して参照する案も、必要のない公開契約拡張になる。

この選定は canonical の `SEC-DATA-006`（Public role は readmodel のみ）と
`THR-019`（Public API への Evidence／Finance 露出防止）に沿う。
元 snapshot の binding・content hash・projection 検証は既存の生成経路が担当し、
表示関数は projection を変更せず読み取る。

## 表示と失敗時の契約

返り値は `更新: <article.updated_public_at> / 状態: <article.freshness_status>`
という HTML テキストで、タグは付けない。両値に標準ライブラリの
`html.escape(..., quote=True)` を適用し、`&`・`<`・`>`・両引用符をエスケープする。
日時の変換、鮮度の再計算、表示値の翻訳や既定値の補完は行わない。

projection／article が mapping でない、article や必須値が欠ける、値が `None`、
空文字、空白のみ、文字列以外の場合は `ValueError` とする。
例外メッセージに入力の値を含めない。既存 OpenAPI の `updated_public_at` は
nullable・任意のままであり、ここでの必須性は更新情報を表示する関数の前提条件である。
projection 全体のスキーマ検証は既存の生成・公開境界に委ね、無関係な値は表示しない。

## 隣接影響

- 現在の recorded projector は `updated_public_at=None`、`freshness_status="UNKNOWN"`
  を返す。そのまま渡すと `ValueError` になる。`published_at` や内部観測値から
  更新日時を作らない。正の回帰ケースだけ、既存 projection のコピーへ合成日時を設定する。
- 公開更新日時が利用できる場合、`UNKNOWN` も渡された状態として表示する。
  呼び出し側は更新日時を持つ projection を渡し、未取得時は `ValueError` を扱う必要がある。
- snapshot／projector／OpenAPI／DB role・grant／生成済み fixture は変更しない。
  既存の public/internal isolation、disclosure、承認、kill switch、default-off を維持する。
- この変更は表示関数の追加であり、公開 route や WordPress テーマへの組み込み、
  publication・staging・deployment・release・Production 操作は行わない。
  URL・画面・スクリーンショットの検証対象はない。
- `tests/st0904_v2/test_static_boundary.py` の import 検査対象に新関数のモジュールを追加し、
  ネットワーク・DB・CMS 依存の混入を既存の検査で検出する。

## ローカル検証

依頼された範囲の回帰テストと `tests/st0904_v2/test_domain.py`・
`tests/st0904_v2/test_static_boundary.py` を既存のローカル依存で並列実行した。
回帰テストは表示形式、両値の HTML escape、非破壊・read-only 入力、欠落・不正値、
他フィールドや内部値からの補完防止、既存 recorded projection の未取得日時を確認する。
ネットワーク・別の保存済み checkout を必要とする検査、`make fast` による範囲拡大、
全件 CI は実行していない。これはローカル検証であり、
formal TST-011／TST-021・hosted CI・staging・Production の証跡ではない。

実行コマンド:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -p xdist.plugin -n 2 \
  --basetemp .harness-task/tmp/pytest-public-update-notice \
  tests/st0904_v2/test_public_update_notice.py \
  tests/st0904_v2/test_domain.py \
  tests/st0904_v2/test_static_boundary.py
```

結果: **43 passed in 1.98s**（回帰31件、domain 8件、static boundary 4件）。
回帰テストの内部フィールドは漏出・補完防止を調べる合成の不正入力であり、
新たな公開フィールドとして認めるものではない。
