# 商品比較の共通形式

2026-09-13のユーザー指示を採用。了承済みコンパクト食洗機の「商品を行に置き、写真・仕様・参考価格・販売先を同じ行で読む」形式を、すべての商品比較子記事と新規比較記事の標準とする。ホーム、カテゴリ、目的別入口、手順だけの記事への商品表の追加は個別の依頼に従う。給水方法の記事は、既存の機種別条件を比較表へ変更する追加指示の対象。

条件別結論は背景パネルを使わず、条件ごとの1列の紹介行にする。同じ商品の写真・ブランドと商品名・正規購入CTA・向く理由と注意点を一緒に置く。比較表は横スクロール不要とし、狭幅でも商品と比較項目が行列で揃う実表として読む。商品カードへの変換や各セルの縦ラベル列は、比較表の代替にしない。カテゴリごとの比較軸を仕様欄へまとめ、各値の項目名を保持する。本体寸法の軸順、主比較と補足、色・世代・セットの違いを保持する。理由の重複節を結論へまとめ、一次出典は1欄に集約する。有用な固有情報と既存アンカーは保持する。

## 最新レビューの扱い

「縦配置」は条件別結論だけに適用する。robotの実3列表を共有で確認後、他の記事へ同じ方式を展開する。商品カード化を解決済みと呼ばず、実際のtable/thead/tr/th/td表示と列位置・行高を確認する。軽量スーツケースは承認済み専用版と各幅で同じ表示に保つ例外として記録する。320pxでは写真が約99pxとなる場合があり、横あふれがないことと写真の読みやすさを区別する。

## 入力と生成

- 商品、型番、公式出典、販売観測、画像確認は `purchase-support.v1.json` の共通商品IDを使う。値を別型番から補わない。
- 既存の生成比較は `commerce_presentation: comparison_rows` と `comparison_row_columns` を指定する。列は `heading` と `fact_labels`。既存の主比較軸の欠落・重複は生成エラーになる。
- 新規記事は [入力ひな型](templates/comparison-row-article.json) と [本文ひな型](templates/comparison-row-article.html.template) を使い、`kind: curated_comparison`、`commerce_presentation: comparison_rows` を指定する。通常本文は `articles/<slug>.html`。画像や金額、広告原文を本文へ直書きしない。
- `row_products` に本文の `data-product-key` と登録商品IDを順番どおり対応させる。主比較と補足は本文の見出し・表グループで分け、主比較の件数へ補足を加算しない。1記事2〜32商品という上限は自動選定を意味しない。
- 各商品行には空の `.ps-row-media[data-product-key]` と `.ps-row-offer[data-product-key]` を1つずつ置く。共有 `row_commerce` が媒体・参考価格・リンクを結合し、表は行と列の対応を保持する。新規ひな型は `responsive_layout: matrix` を指定し、共通処理で商品・写真／仕様／参考価格・販売先の3列へ整理する。既存の仕様セルの値・出典・IDを保持し、条件別結論には触れない。`authored` は確認済み専有レイアウトを保持する例外である。旧コンパクトのスロットも同じ商用処理を使う。
- 条件紹介の各商品に `condition_slots: [{key, product_id}]` を登録し、`.ps-condition-product-media[data-ps-media-product][data-ps-condition]` と `.ps-condition-product-purchase[data-ps-purchase-product][data-ps-condition]` を空で置く。画像原文は `condition_media` にハッシュ固定して投影し、結論と表で別のCTA識別子を生成する。結論では価格数値を重複しない。
- `scripts/build_reader_purchase_support_v1.py` の入力・出力に新規記事を追加し、通常の記事台帳へ登録する。

本文・商品データの更新後は、次の順で生成する。テーマが保持する共通データの照合用ハッシュも更新するため、本文だけの変更でもテーマ生成を行う。最後にテーマ生成だけを再実行すると依存manifestが古くなるので、依存生成まで続ける。

```sh
.venv/bin/python scripts/build_reader_purchase_support_v1.py
.venv/bin/python scripts/build_st1704_self_hosted_theme.py --generate
make generate
```

プレビューでは本文の表示だけでなく、商品画像・補助CSS・価格JSの読み込みと、共通データのハッシュ一致を確認する。

## 給水ガイドの比較表

`dishwasher-water-supply-methods` は `kind: guide` を維持し、`commerce_anchor: guide-evidence` に商品表を置く。`product_ids` は従来の4機種、`supplementary_product_ids` はSS-LH451の1例。`row_products` は主対象と補足を合わせた行順にする。補足行には `data-ps-supplementary="true"` を付け、旧アンカーを保持する。

主4行の `details.ps-guide-facts` は共通カタログの給水・排水手順と出典から更新する。早見欄の `data-ps-guide-field` は `water_supply` または `drainage` を指定し、参照条件が欠損・UNKNOWNになったときは古い説明を撤回する。別に確認したラクアmini colorの補助ポンプとSS-LH451の補足説明は、対応する出典とともに通常本文で保持する。

公開runtimeの `guide_product_scope` は主対象1〜4件・補足0〜1件を明示する。PHPは重複・範囲外の画像を拒否し、従来のガイドは従来上限を維持する。5枚目の補足画像も、対象記事の画像台帳への登録と実ブラウザでの読み込み確認が必要。既存snapshotとテーマのハッシュ照合を省略しない。

## 素材と参考価格

画像は型番・色・世代・構成および利用根拠が確認できた原文だけを登録する。画像が未確認でも、独立して確認した販売先・公式仕様へのリンクは残す。広告URLは正規発行値とsnapshot bindingを維持する。

既存の登録画像を新規記事へ使うときも、画像台帳の `slugs` にその記事を明示して登録し直す。登録内容のハッシュと商品側の確認記録を更新し、対象外記事への自動流用は行わない。

本体単体の税込参考価格は、確認済み販売ページの同一SKUを出典・日時つきで共通カタログへ登録する。商品状態UNKNOWNや売り切れでも参考表示できるが、購入可能・新品・購入総額・予算内へ昇格させない。確認後最大24時間と提供元の期限の早い方まで。JS無効時は数字を出さず、失効・再訪・タブ復帰時に数字を消す。クーポン・ポイントを差し引かない。価格や期限の処理を記事別に複製しない。

## 確認と公開

商品行のID・型番・画像・参照SKU・CTA・snapshot一致、同一IDの重複、全旧アンカー、価格期限、JS無効、320/390/768/1440pxの実表表示・列位置・行高・横あふれ・条件1列・各商品の全仕様の可読性を確認する。追加の素材が未確認なら不足を商品別に記録し、結合完了とは呼ばない。共通基盤変更は関連テストと `make fast` を実行する。

ローカル候補を示してから、確認済み候補への具体的な公開指示に従い `owner-direct-v1` で反映する。

画像だけを別の販売ページから追加確認した場合は `verified_image_reference` に同一型番・色/構成・状態・実画像確認日と取得元を記録する。中古掲載品の写真は短いキャプションで明記し、元の販売観測や参考価格を更新したことにはしない。媒体原文・取得元URL・登録ハッシュの照合は維持する。
