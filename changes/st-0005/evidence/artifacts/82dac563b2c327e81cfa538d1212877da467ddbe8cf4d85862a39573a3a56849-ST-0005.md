## Effective-state boundary

The workspace has no real Git repository, pull request, CI execution, or
human approval artifact. It would be unsafe to convert local implementation
results into effective status. Five independent `PROPOSE` requests therefore
record hash-bound local evidence for ST-0001 through ST-0005 while all five
effective rows remain canonical `NOT_STARTED / NOT_EXECUTED`.

The overlay retains all 129 Story rows, 32 Test Suite rows, and six environment
rows with complete canonical record hashes. Proposal histories are additive
and cannot delete unresolved rows.

The offline validator declares the full structural transition grammar and
replays committed non-deployment history deterministically, but the live
workflow rejects every newly added authoritative `APPLY`. Activation is
explicitly deferred to `ST-0006` and `ST-0107`. Implementation transitions
involving a deployed status remain blocked offline and live pending typed gates
from `ST-1505`, `ST-1506`, and `ST-1607`; verification-only regression or
expiry while implementation remains deployed is not blocked by that rule.
