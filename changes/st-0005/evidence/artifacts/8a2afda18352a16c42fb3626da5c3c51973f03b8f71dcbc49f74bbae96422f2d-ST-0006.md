# ST-0006 ExecPlan — Open-decision gate validator

## 1. Story and outcome

- Story: `ST-0006`, `EPIC-00`, P0/M, MVP.
- Objective: reflect unresolved blocking decisions in Release/Gate checks.
- Dependency: `ST-0005`.
- Design: `RAOS-OPEN-DECISIONS-001`.
- Deliverables: strict decision loader and gate blocker report.
- Acceptance: release is unavailable while an unresolved blocking decision
  exists.
- Required suites: `TST-005` (formal CI) and `TST-032` (formal staging).

## 2. Scope resolution

The canonical Story, integration rules, open-decision source, master parity
CSV, status taxonomy, Gate test design, test catalog, operations boundary,
ST-0005 handoff, and downstream ST-0107/ST-1607 responsibilities were read.
The current source contains 15 decisions, 14 with `blocking: true`, no
`RESOLVED` item, and one unresolved nonblocking item (OD-004).

ST-0006 does not invent or approve a decision, define a resolution-record
format, create the full Gate evidence pack, activate live status `APPLY`, add
CI/PR governance, deploy anything, or claim Gate/Production readiness.

## 3. Design

The generator is self-contained so the later ST-0006 status proposal can
extend ST-0005 without making this bundle depend recursively on the mutable
ST-0005 manifest. It first performs complete ST-0001 import verification and
pins the design manifest, open-decision YAML/CSV, status taxonomy, test suite
catalog, and Story catalog.

The loader rejects non-regular/symlinked/oversized sources, malformed UTF-8,
duplicate YAML keys, anchors/aliases, excessive pre-construction token nesting
or post-construction depth/nodes, CSV shape drift, missing/unknown fields,
invalid IDs, loose booleans, unknown status values, empty/unsorted/duplicate
inventory, hash drift, and YAML/CSV semantic mismatch. Canonical YAML/CSV
parsing and hashing use the same stable descriptor snapshot; pinned files are
rechecked when the manifest is assembled.
`RESOLVED` alone is resolved; `PROVISIONAL`, human-decision-required, and
external-evidence-required states remain unresolved.

`required_by` is free text rather than a typed relation. The report preserves
it but never parses it. The canonical rule that blocking decisions prohibit
Production/Gate passage is implemented conservatively: every unresolved
blocking decision applies to `GATE-0..4` and `PRODUCTION_RELEASE`. A future
human-reviewed typed mapping may narrow that policy; this Story cannot infer
one.

Generated contracts, policy, report, and manifest are built completely in a
sibling staging directory. Current-version schemas bind the exact pinned
15-decision inventory and exact 14-blocker/six-target closure, not merely the
shape of a generic report. Existing generated ownership, complete flat
inventory, file type, and hash are verified first. Installation pins the
bundle/staging directories with non-symlink descriptors, uses
descriptor-relative replacements, and rolls back on any ordinary exception or
interrupt after replacement starts. Rollback continues best-effort across every
entry and byte-verifies the previous tree. A double filesystem failure that
prevents full restoration retains the sibling backup/staging directory and
reports its exact recovery path instead of deleting it during stack unwinding.

As with the workspace bootstrap, a same-UID actor with arbitrary concurrent
repository rename/write access is outside the security boundary because it can
already alter the workspace directly. The generator must not run alongside
such an adversarial mutator. The tested bundle-root rebinding window is still
contained: writes remain on the pinned directory inode, identity drift triggers
rollback, and an attacker-selected external directory is not modified.

## 5. Verification plan

- exact current 15/14/0 baseline and YAML/CSV parity;
- strict-loader negative cases for structure, types, status, identity,
  resources, symlinks, and hash drift;
- synthetic `RESOLVED`, `PROVISIONAL`, nonblocking, all-clear, mixed, and
  opaque-`required_by` unit cases;
- exact six-target fail-closed mapping and generated-schema validation;
- deterministic generation, owned-tree enforcement, failure preservation,
  install rollback, and manifest byte/hash coverage;
- ST-0005, importer, prior Story, static-analysis, and protected-artifact
  regressions;
- append-only local status proposal without effective status change;
- independent artifact/security review.

## 6. Evidence boundary

Local checks may support only `IMPLEMENTED_NOT_VALIDATED / NOT_EXECUTED`.
Formal TST-005 requires CI; formal TST-032 requires staging and the later full
Gate pack. No GitHub PR/CI, human decision, exception, Gate acceptance,
release approval, staging, or production evidence will be claimed.
