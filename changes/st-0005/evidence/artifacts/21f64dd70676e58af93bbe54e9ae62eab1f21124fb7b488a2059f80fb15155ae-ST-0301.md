## Scope and decisions

The implementation provides Alembic versioning, per-revision transactions, a
same-session advisory lock, append-only history, and empty-to-framework-head.
It intentionally creates no RAOS domain schema. ST-0302 owns MIG-001 and
ST-0303/ST-0304 own IAM/OPS and domain schemas.

Read-only parallel review corrected five issues before runtime implementation:

1. migration metadata uses `public` tables instead of inventing a fourteenth
   RAOS schema or using later-owned `ops`;
2. database targets use explicit constrained fields and a 0600 password file,
   not ambient libpq configuration or a DSN;
3. Alembic `on_version_apply` commits successful history atomically with the
   version row and revision DDL;
4. mixed-transaction ST-0002 through ST-0004 payload execution is disabled;
   all 18 remain path/hash-bound deferred inputs with direction-specific plans;
5. the production graph contains one necessary root/head rather than an
   artificial test revision. The root is a retained history anchor and uses
   forward recovery.
