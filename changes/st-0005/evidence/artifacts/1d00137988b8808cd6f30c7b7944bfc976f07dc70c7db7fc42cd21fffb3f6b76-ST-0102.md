# ST-0102 ExecPlan — Pin Python toolchain

## 1. Story and outcome

- Story: `ST-0102`, `EPIC-01`, P0/S, MVP.
- Objective: pin Python, uv and its lockfile, Ruff, a type checker, and pytest.
- Dependency: `ST-0101`; its workspace bootstrap is locally implemented and
  drift-free, while canonical effective status remains unchanged.
- Required suites: `TST-001` and `TST-005` (formal environment: CI).
- Acceptance criterion: a deterministic install from a committed lockfile.
- Outcome: exact tool/runtime versions, a uv-generated lock, locked commands,
  scoped static checks, and Story-local contract tests.

## 2. Context and scope resolution

The canonical Story row, critical path, TST-001/TST-005 catalog entries,
repository architecture and dependency rule, dependency-pinning security
control, root/canonical AGENTS, ST-0101 handoff, and current Python imports were
reviewed. ST-0102 has no attached Open Decision.

The architecture requires stable package-manager versions selected at
implementation time and a committed lockfile. Official release records were
therefore used to resolve exact versions as of 2026-08-02: CPython 3.14.6, uv
0.12.1, Ruff 0.16.1, pytest 9.1.1, and mypy 2.3.0. Mypy is selected from the
approved TST-001 alternatives so ST-0102 does not introduce the Node runtime
owned by ST-0103. Existing direct third-party imports determine the remaining
locked dependencies: PyYAML, jsonschema, and referencing; types-PyYAML supplies
typed YAML imports without a global missing-import suppression.

ST-0102 is only the Python repository toolchain. Product packages, generated
types, application dependencies, contracts, Node, base CI, service runtimes,
provider integrations, and deployment remain with later Stories.

## 3. Design

`pyproject.toml` is the human-maintained project and static-tool source of
truth. `uv.toml` is the sole uv resolution/install configuration; Make passes
its absolute path with `--config-file`, which disables automatic user/system
configuration discovery. Together they declare an intentionally non-packaged
uv workspace, exact Python and direct dependency versions, the sole default
package index, and exact uv/Ruff/pytest requirements. `uv.lock` is generated by
the exact uv release and is never hand-edited. `.python-version` pins the
managed interpreter selected by uv.

The uv project rejects a mismatched uv binary, ambient system interpreters,
implicit Python downloads, prereleases, local/Git/URL source overrides, and
artifacts newer than the recorded resolution cutoff. The configured default
index is `https://pypi.org/simple`; lock validation additionally requires
registry sources and SHA-256 hashes. Environment or command-line index
overrides remain an operator boundary and are explicitly cleared by the
repository commands.

The Makefile separates mutable bootstrap/generation operations from read-only
or locked verification. `python-install` is the only command that may fetch a
managed interpreter; `python-lock` is the only lock regeneration target.
Normal setup uses `uv sync --locked` with downloads disabled for the Python
interpreter. Each Make check runs that locked sync prerequisite once, then the
tool gate executes with `--locked --no-sync`. The Make entrypoint derives paths
from its own file, quotes them, protects internal helpers, and rejects preloaded
makefiles or Make modes that skip commands, ignore failures, touch targets, or
let the ambient environment replace definitions. A fixed-command shell wrapper
is the recorded-evidence entrypoint: it validates the uv binary and clears GNU
Make inputs that are otherwise processed before the repository Makefile. It
uses Linux `/bin/bash -p` so startup files, inherited shell options, and
exported functions cannot execute before validation. Story test directories
remain isolated processes because their module names overlap. ST-0102 does not
create base CI or claim cross-platform execution.

Ruff lint covers owned Python source, repository scripts, and tests. Formatting
is check-only and limited to ST-0102-owned Python files so pre-existing Story
formatting and content-addressed artifacts are not rewritten. Mypy uses strict
checking for production Python source; repository maintenance scripts are not
silently declared typed by this Story. Pytest has strict configuration and
plugin autoload is disabled for deterministic Story runs.

## 5. Verification plan

- parse and enforce all exact versions and safe uv settings;
- verify the generated lock is current, registry-only, hash-bearing, and
  consistent with every direct pin;
- reject an older uv binary and a deliberately drifted project definition;
- install into fresh temporary environments twice from the lock, with the
  second sync offline from a hydrated cache, and compare installed inventories;
- assert exact Python/tool versions through locked no-sync execution;
- run Ruff lint, scoped format check, strict mypy, and isolated ST-0102 pytest;
- run imported-design verification, all prior generators in check mode, all
  prior Story suites in isolated processes, and the protected-file checksum;
- validate the append-only status request, regenerate/check the ST-0005 bundle,
  and obtain an independent code/security/evidence audit.

## 6. Evidence boundary

Local checks can support an `IMPLEMENTED_NOT_VALIDATED` proposal only. Formal
TST-001 and TST-005 execute in CI, but this workspace has no usable Git metadata,
hosted pull request, or base CI implementation. Effective canonical status and
formal suite status remain `NOT_STARTED` / `NOT_EXECUTED`; no CI, staging,
release, or production claim will be made.
