# ST-0203 ExecPlan - Local queue abstraction

## Story and outcome

- Story: `ST-0203`, `EPIC-02`, P0/M, MVP, one-PR preferred.
- Objective: reproduce at-least-once delivery with a deterministic Queue fake.
- Dependency: `ST-0102`; no open decision is attached to this Story.
- Deliverables: queue port, fake adapter, and duplicate fixture.
- Acceptance: explicit duplicate and out-of-order injection.
- Required suite: release-blocking `TST-013` in CI, covering duplicate,
  out-of-order, retry, DLQ, and lease behavior.

The scoped outcome is a local/CI test double. It is not a broker, worker
runtime, idempotency store, or production queue adapter.

## Preflight

1. Read the master/integration decisions, open-decision register, exact
   ST-0203 Story, TST-013, relevant security controls, Job Message, Job
   Catalog, Job state revision, and Codex implementation handbook.
2. Preserve `zip/**`, `docs/canonical/**`, `docs/upstream/**`, and
   `docs/manifest.json` byte-for-byte.
3. Keep provider SDK types out of the port and keep the fake free of network,
   threads, sleeps, wall-clock reads, and credentials.
4. Model delivery mechanics only. Consumer idempotency and Job/Inbox/Outbox
   state transitions remain later-Story responsibilities.
5. Add positive, duplicate, order, lease, retry, DLQ, and invalid receipt
   tests; do not convert a local result into formal TST-013 evidence.

## Implementation

1. Define the complete semantic source at
   `changes/st-0203/contracts/local-queue.v1.yaml`.
2. Define immutable generic messages/deliveries and a provider-neutral
   `QueuePort` Protocol in `python/raos/ports/queue.py`.
3. Implement the explicit-manual-clock fake in
   `python/raos/adapters/queue_fake.py`.
4. Preserve logical message/idempotency identity across duplicate
   occurrences while issuing a distinct receipt per delivery occurrence.
5. Make lease expiry and retry deterministically redeliver until the attempt
   budget moves the occurrence to the inspectable DLQ.
6. Generate one deterministic Story manifest, pinned to canonical queue
   contracts and the ST-0202 evidence predecessor.
7. Add the isolated suite to the existing offline Unit job; do not add an
   external broker job.

## Completion boundary

Local deterministic execution can establish an implementation candidate. It
cannot establish durable provider behavior, IAM separation, consumer
idempotency, worker correctness, formal TST-013, release, staging, or
production status.
