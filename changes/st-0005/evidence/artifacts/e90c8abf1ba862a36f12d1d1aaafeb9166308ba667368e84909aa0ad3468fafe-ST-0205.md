## Implementation notes

- Exact 13-domain order: ops, iam, portfolio, catalog, evidence, editorial,
  ai, policy, publishing, freshness, analytics, finance, readmodel.
- The versioned bundle has reviewed Time/Currency/Locale/Unicode/Large-value/
  DST/JST/duplicate/out-of-order scenarios.
- Payload keys are reconstructed in canonical allowlist order before output;
  serialized JSON key ordering is deterministic and not a security boundary.
- Structural forbidden-key checks normalize NFKC, camel-case boundaries, and
  separators. Canonical privacy metric names such as `review_count`,
  `email_verified`, and policy text `NO_REVIEW_BODY` are not substring-blocked.
- Secret checks reuse the repository scanner and error messages never include
  input canaries. Valid IPv4 and IPv6 literals are rejected using the standard
  library parser; invalid dotted/version strings are not treated as addresses.
- Missing classification normalizes to CONFIDENTIAL. Explicit RESTRICTED data
  gets a distinct fail-closed rejection; arbitrary unknown classes fail as
  unknown.
