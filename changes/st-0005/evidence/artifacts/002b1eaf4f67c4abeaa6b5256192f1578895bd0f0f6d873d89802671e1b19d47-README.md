# RAOS monorepo

This repository implements the approved RAOS design one canonical backlog
Story at a time. Imported design packages are immutable inputs; working code,
contracts, tests, and operational evidence are added outside those roots.

## Bootstrap

ST-0101 provides a toolchain-neutral, offline workspace bootstrap. It uses only
the Python standard library, downloads nothing, installs no dependency, loads
no credential, and starts no service.

```bash
make bootstrap
make check-workspace
```

If `make` is unavailable, the equivalent commands are:

```bash
python3 scripts/bootstrap_workspace.py
python3 scripts/bootstrap_workspace.py --check
```

`workspace-layout.json` is the source of truth. Bootstrap creates missing
generated `README.md` directory markers and rejects drift instead of replacing
an existing entry. It rejects unsafe paths, symlink traversal, file collisions,
immutable design roots, unmanaged marker replacement, and hard-linked managed
markers. Missing markers are fully written to an anonymous inode before an
atomic create-if-absent publication; the private file-descriptor window is
closed before process visibility is restored. Re-running bootstrap is
idempotent; `--check` is read-only and fails on missing or drifted output.

The bootstrap command itself can still use an existing `python3` because it is
a standard-library recovery path. Descriptor-safe traversal requires `O_DIRECTORY` and
`O_NOFOLLOW`. Creating a missing marker additionally requires Linux `prctl`, a
filesystem supporting `O_TMPFILE`, and mounted procfs support for
`/proc/self/fd`; unsupported write environments fail closed without falling
back to a named temporary file. Read-only `--check` does not require
`O_TMPFILE`, procfs publication, or `prctl`. Python version and dependency
locking for other Python commands is provided by ST-0102; Node and npm locking
is provided independently by ST-0103.

Bootstrap is a single-process repository maintenance command. As with direct
filesystem access generally, an actor running under the same UID can rename or
mutate the workspace itself and is not a security boundary. Do not run it
concurrently with another same-UID workspace mutator. Descriptor pinning and
final inode checks make detected races fail, but a directory moved after it is
opened can retain a newly created marker on that pinned inode.

| Path | Responsibility |
|---|---|
| `apps/` | Web, API, and worker delivery boundaries |
| `packages/` | Shared web UI, generated web contracts, and policy schemas |

Reserved directories are intentionally inert. Their presence does not mean a
toolchain, contract, provider, database, queue, deployment, or product feature
is implemented.

## Pinned Python toolchain

ST-0102 pins CPython 3.14.6, uv 0.12.1, Ruff 0.16.1, mypy 2.3.0, and pytest
9.1.1. `pyproject.toml` owns project/static-tool configuration, `uv.toml` owns
uv's resolution/install configuration, and `uv.lock` is the unaltered
uv-generated dependency lock. The root is currently a virtual uv project:
`python/raos` is the production source boundary, but packaging and product
dependencies are added only by their owning Stories.

Install the exact uv binary through an independently checksum-verified release
artifact, then use the repository commands:

```bash
scripts/python_toolchain.sh --uv /absolute/path/to/uv install
scripts/python_toolchain.sh --uv /absolute/path/to/uv sync
scripts/python_toolchain.sh --uv /absolute/path/to/uv check
```

The wrapper requires an absolute uv executable path, verifies uv 0.12.1 before
invoking a fixed Make target, and removes GNU Make's inherited pre-parse control
inputs. It requires Linux `/bin/bash` and uses privileged startup mode so
`BASH_ENV`, inherited shell options, and exported functions cannot run before
its validation. `install` is the explicit managed-interpreter download step.
Normal sync requires that interpreter to exist, rejects a stale lock, and
disables implicit Python downloads. Each check target deliberately runs the
locked `python-sync` prerequisite once; its subsequent tool invocation uses
`--no-sync` and cannot rewrite the lock.
`scripts/python_toolchain.sh --uv /absolute/path/to/uv lock` is the intentional
lock-regeneration operation; review and commit the complete generated
`uv.lock` after it runs.
After one successful online sync has hydrated the current platform cache,
Wrapper command `sync-offline` recreates the fixed, repository-local
`.venv-offline-check` environment and proves it can be synchronized with
network access disabled. It rejects a symlink at that managed path and is not
a cold-install substitute.
The configured source is the Python Package Index, and the commands clear uv
config, source, resolution, hash-verification, interpreter, and dependency-group
override variables before locking or installation. It also removes Python and
pytest injection variables, disables uv dotenv loading, and does not honor an
ambient environment destination. Every Make command supplies the absolute
repository `uv.toml` as uv's sole configuration file, disabling automatic user
and system configuration discovery. The evidence wrapper removes inherited
`MAKEFILES`, `MAKEFLAGS`, and `GNUMAKEFLAGS`; the Makefile additionally rejects
preloaded makefiles, direct `MAKEFLAGS` assignments, and GNU Make's
environment-override, ignore-error, dry-run, and touch modes because those
modes cannot produce verification evidence. Parallel make remains supported.
Direct Make commands remain developer conveniences, while recorded
verification must use the wrapper. Do not use `--frozen` as a substitute for
`uv lock --check`: frozen mode trusts the existing lock and does not prove it
matches `pyproject.toml`.

The local Python check runs Ruff lint, a format check limited to current Python
source/ST-0102 tests, strict mypy on `python/raos`, and the isolated ST-0102
suite. Base CI and its supported operating-system matrix remain ST-0106 scope.

## Pinned Node toolchain

ST-0103 pins Node 24.18.1 LTS and its bundled npm 11.16.0. The private root npm
workspace is deliberately limited to `apps/web` and `packages/web-ui`.
`apps/web/package.json` pins Next.js 16.2.12, React 19.2.8, and React DOM
19.2.8; no application route, component, or server is created by this Story.
Root development tools pin TypeScript 6.0.3, ESLint 9.39.5 with the matching
Next.js flat config, Prettier 3.9.6, Vitest 4.1.10, Vite 8.2.0, and Pyright
1.1.411. Exact transitive overrides keep PostCSS at 8.5.25 and Sharp at 0.35.3
because Next.js 16.2.12 still declares advisory-affected releases. The
implementation-time official-source and advisory record is
`docs/architecture/ST-0103-toolchain-snapshot.yaml`.

Use independently checksum-verified Node and its bundled npm CLI through the
recorded-evidence wrapper:

```bash
scripts/node_toolchain.sh \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js sync
scripts/node_toolchain.sh \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js check
```

The wrapper requires both absolute paths and verifies Node 24.18.1 and npm
11.16.0 before invoking a fixed repository target. It uses Linux
`/bin/bash -p`, clears shell/Node/npm/GNU Make pre-parse inputs, disables
Corepack network use and Next.js telemetry, and fixes npm's registry,
configuration, cache, and install behavior. Dependency lifecycle scripts are
disabled. Direct npm and Make commands are developer conveniences; recorded
verification uses the wrapper.

`sync` uses `npm ci`, so its deletion scope is the fixed root `node_modules`
tree plus any `node_modules` tree below the two allowlisted workspaces. Before
npm runs, the gate rejects symlinks at the cache, every deletion target, each
workspace parent, and each fixed package input. It fails when `package.json`
and `package-lock.json` disagree and never updates the lock. Run it only as a
single-process repository maintenance command without a concurrent same-UID
Node workspace mutator. The intentional lock-regeneration operation is:

```bash
scripts/node_toolchain.sh \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js lock
```

Review and commit the complete npm-generated `package-lock.json`; never edit it
by hand. After an online `sync` hydrates the fixed cache, wrapper command
`sync-offline` installs into a fresh temporary workspace with npm network access
disabled and compares the normalized installed dependency tree with the online
tree. This is a same-platform warm-cache reproduction proof, not a cold or
cross-platform install claim.

The Node `check` command performs the locked sync, exact version gate, complete
`npm ls --all` dependency-tree validation, check-only formatting, Next.js
ESLint, strict TypeScript, Pyright, and the isolated ST-0103 Vitest suite. It
does not run a Next.js build because product routes and components belong to
later Stories.

## Design and verification

Start with `docs/README.md`, then follow the selected Story's canonical read
order and the root `AGENTS.md`. Verify the imported package independently:

```bash
python3 scripts/import_raos_design.py verify
```

Story tests run in separate pytest processes because suite-local module names
overlap. The current local Story checks include:

```bash
uv run --locked --no-sync pytest -q tests/st0101
scripts/python_toolchain.sh --uv /absolute/path/to/uv test
scripts/node_toolchain.sh --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js test
```

Those local results are not formal TST-001/TST-005 CI evidence. The local
ST-0103 result is likewise not formal TST-006 CI evidence. Base CI is deferred
to ST-0106, PR governance to ST-0107, and runnable local services to ST-0201
and later Stories. A local
temporary Git repository can verify clean-clone mechanics, but local bootstrap
alone does not prove the delivered repository's tracked-file set, a hosted
remote clone, pull request, or CI run. Those require separate evidence.

## Safety boundaries

- Never edit `zip/**`, `docs/canonical/**`, `docs/upstream/**`, or
  `docs/manifest.json`.
- Never commit credentials, production data, review bodies, raw prompts, or
  personal data.
- Publishing, production changes, policy activation, and release decisions
  remain human-approved actions.
