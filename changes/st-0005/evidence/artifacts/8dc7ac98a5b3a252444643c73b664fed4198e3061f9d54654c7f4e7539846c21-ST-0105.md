## Implementation

The exact Python environment now includes Pydantic 2.13.4 and
datamodel-code-generator 0.71.0. The exact Node workspace includes
`@hey-api/openapi-ts` 0.99.0 and a private `@raos/web-contracts` package.
Both generated dependency locks were regenerated by their owning exact tools.

The code generator verifies exact observed CPython, Pydantic,
datamodel-code-generator, Node, TypeScript, and OpenAPI generator identities,
the pinned ST-0104 manifest,
the loader's complete artifact integrity, safe/collision-free paths, expected
corpus counts, OpenAPI operation IDs, and AsyncAPI structure before producing:

- 302 Python files containing 224 stable top-level Pydantic schema bindings;
- 52 TypeScript files containing all schema types, three self-contained fetch
  clients with 6 Public, 171 Admin, and 8 Internal operations, and an AsyncAPI
  registry with 22 channels, 37 operations, and 105 messages; and
- one canonical manifest with 354 exact output file hashes, source bindings,
  intermediate hashes, and exact tool versions.

Generation happens in a private temporary tree with network retrieval disabled.
The read-only mode compares the regenerated manifest and both complete trees.
The mutating mode locks the manifest parent, opens all managed ancestors with
`O_NOFOLLOW`, retains pinned descriptors, and publishes a durable four-state
journal before staging or replacement. Pre-commit crashes roll back on the next
install-side invocation; committed crashes finish cleanup. Recovery attempts
both trees and the manifest independently, records terminal state only after
full verification, and preserves the journal/stages if any recovery step fails.

Generated sources are not hand-edited or post-formatted. Python files are
checked by exact regeneration/hash inventory, Ruff lint, in-memory compilation,
import of every stable binding, and all Pydantic JSON Schema builds. They are
excluded from hand-maintained formatter/mypy/Pyright scope. TypeScript inherits
the strict root config; only `exactOptionalPropertyTypes` is disabled for the
isolated generated fetch-client package because the pinned generator's optional
property assignments do not satisfy that flag.

`scripts/codegen_toolchain.sh` is the recorded command boundary. It requires
absolute exact uv/Node/npm paths, binds npm to the selected Node installation,
and uses an allowlisted environment. `hydrate` is the explicit Python/Node/cache
mutation, `install` mutates only generated outputs, and `check`, `test`,
`typecheck`, and `gate` consume the installed environment offline with no cache
or synchronization. The package marker remains generated from
`workspace-layout.json` and now records ST-0105 ownership and no-hand-edit
rules.
