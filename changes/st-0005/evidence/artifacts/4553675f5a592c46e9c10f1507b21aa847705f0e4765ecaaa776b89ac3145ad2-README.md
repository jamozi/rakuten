# RAOS monorepo

This repository implements the approved RAOS design one canonical backlog
Story at a time. Imported design packages are immutable inputs; working code,
contracts, tests, and operational evidence are added outside those roots.

## Bootstrap

ST-0101 provides a toolchain-neutral, offline workspace bootstrap. It uses only
the Python standard library, downloads nothing, installs no dependency, loads
no credential, and starts no service.

```bash
make bootstrap
make check-workspace
```

If `make` is unavailable, the equivalent commands are:

```bash
python3 scripts/bootstrap_workspace.py
python3 scripts/bootstrap_workspace.py --check
```

`workspace-layout.json` is the source of truth. Bootstrap creates missing
generated `README.md` directory markers and rejects drift instead of replacing
an existing entry. It rejects unsafe paths, symlink traversal, file collisions,
immutable design roots, unmanaged marker replacement, and hard-linked managed
markers. Missing markers are fully written to an anonymous inode before an
atomic create-if-absent publication; the private file-descriptor window is
closed before process visibility is restored. Re-running bootstrap is
idempotent; `--check` is read-only and fails on missing or drifted output.

The bootstrap command itself can still use an existing `python3` because it is
a standard-library recovery path. Descriptor-safe traversal requires `O_DIRECTORY` and
`O_NOFOLLOW`. Creating a missing marker additionally requires Linux `prctl`, a
filesystem supporting `O_TMPFILE`, and mounted procfs support for
`/proc/self/fd`; unsupported write environments fail closed without falling
back to a named temporary file. Read-only `--check` does not require
`O_TMPFILE`, procfs publication, or `prctl`. Python version and dependency
locking for other Python commands is provided by ST-0102; Node and npm locking
is provided independently by ST-0103.

Bootstrap is a single-process repository maintenance command. As with direct
filesystem access generally, an actor running under the same UID can rename or
mutate the workspace itself and is not a security boundary. Do not run it
concurrently with another same-UID workspace mutator. Descriptor pinning and
final inode checks make detected races fail, but a directory moved after it is
opened can retain a newly created marker on that pinned inode.

## Repository map

| Path | Responsibility |
|---|---|
| `apps/` | Web, API, and worker delivery boundaries |
| `packages/` | Shared web UI, generated web contracts, and policy schemas |
| `python/raos/` | Domain, application, inward ports, outward adapters, and delivery code |
| `contracts/` | Versioned, hash-bound contract repository installed by ST-0104 |
| `prompts/`, `policies/`, `schemas/` | Versioned definitions and contract boundaries |
| `migrations/` | Reserved migration boundary for ST-0301 |
| `infra/` | Docker and Terraform boundaries; no service or apply is activated here |
| `tests/` | Story suites plus contract, E2E, security, evaluation, and fixture areas |
| `docs/` | Imported design, ADRs, architecture notes, runbooks, plans, and work logs |
| `changes/` | Story-owned revisions, manifests, and operational overlays |
| `scripts/` | Repository generators, validators, importers, and bootstrap commands |

Reserved directories are intentionally inert. Their presence does not mean a
toolchain, contract, provider, database, queue, deployment, or product feature
is implemented.

## Installed contract repository

ST-0104 installs the pinned cumulative ST-0004 contract candidate without
rewriting it. `contracts/raos-v0.4/job-state.v1.yaml` and the 305 files below
`contracts/raos-v0.4/contracts/` remain byte-identical to the source bundle;
their relative two-level shape preserves job-state references embedded in the
OpenAPI, AsyncAPI, and resource catalogs. The generated
`contract-repository.v0.4.json` owns the exact 306-payload inventory and binds
each path to its byte length and SHA-256. It also declares the exact six
reviewed offline retrieval-URI aliases needed by the byte-frozen schemas; the
canonical `$id`, referring path/reference, and target path are all explicit.
`contracts/README.md` remains the ST-0101 workspace marker and is outside that
version-tree ownership.

For recorded execution, pass an independently verified exact uv 0.12.1 binary
through the Python evidence wrapper. Installation is intentional; the other
commands are read-only gates:

```bash
scripts/python_toolchain.sh --uv /absolute/path/to/uv contract-install
scripts/python_toolchain.sh --uv /absolute/path/to/uv contract-check
scripts/python_toolchain.sh --uv /absolute/path/to/uv contract-verify
scripts/python_toolchain.sh --uv /absolute/path/to/uv contract-test
scripts/python_toolchain.sh --uv /absolute/path/to/uv contract-gate
```

The equivalent `make contract-*` targets remain trusted local developer
conveniences when the configured `uv` is the exact pinned version and the
locked environment has already been hydrated. The read-only contract targets
run `uv` with `--offline --no-cache --no-sync`; only `contract-install` retains
the explicit synchronization prerequisite.

The installer verifies the pinned ST-0004 manifest and source tree before a
durably fsynced sibling-staged replacement. An existing tree is exchanged with
Linux `renameat2(RENAME_EXCHANGE)`, so readers never observe a missing install;
a fresh install uses one atomic rename. It rejects unsupported exchange,
unknown, missing, mutated, oversized, symlinked, non-regular, escaping, or
case-fold-colliding files. `--check` regenerates independently and performs a
byte comparison without changing the installed tree. Run `contract-install`
as a single-process repository maintenance command without a concurrent
same-UID workspace mutator.

The standard-library loader in `python/raos/shared` exposes only manifest-owned
read-only artifacts, registered JSON Schema IDs, and those six explicit
aliases. The ownership manifest is the loader's trusted deployment input; the
composite `contract-gate` is the command that independently reconstructs it
from the pinned ST-0004 source and therefore attests source byte parity. The
verifier uses the locked development environment to parse all contract
formats, resolve 3,844 local `$ref` occurrences, resolve all 344 Draft 2020-12
schema references by canonical URI with networking disabled, and check 337
declared path/hash bindings. The traceability CSV contributes 111 installed
local references and one explicitly allowlisted external provenance proposal.
It validates the full structure of the three OpenAPI 3.1.1 documents and the
AsyncAPI 3.0.0 document with exact official schemas stored under
`scripts/contract_validation_resources/`; those schema bytes are independently
SHA-256 pinned and retain their Apache-2.0 licenses. OpenAPI inline Schema
Objects are validated using each document's required Draft 2020-12 dialect.
The closed-corpus role pass binds all 2,940 OpenAPI references as 492 Schema,
486 Parameter, 1,434 Response, and 528 Header references. It separately binds
all 557 AsyncAPI references as 37 operation-channel, 249 operation-message,
144 channel-message, 22 channel-server, and 105 message-payload references.
Together with 344 standalone JSON Schema references and three references among
seven meta-validated embedded public-resource schemas, this role-classifies
all 3,844 physical `$ref` occurrences. The separate semantic path pass requires
all 192 references to remain at their frozen document/JSON-Pointer locations;
all 99 schema-bearing catalog paths and all 12 prompt-frontmatter output paths
must resolve to exact standalone schema-document roots. The seven embedded
schemas must also stay within the JSON data model, including string-only object
keys, before Draft 2020-12 meta-validation.
Wrong-category targets, operation messages crossing their declared channel,
and non-schema Reference Object cycles fail closed. Exact boolean OpenAPI
component schemas remain valid; boolean annotation fields and schema fragments
outside this frozen root-reference contract are not accepted as schemas.
It does not activate an AI/content runtime, generate Python/TypeScript types,
apply a canonical proposal, or configure CI. Those remain later Story scope;
the local gate is not formal TST-002 CI evidence.

## Pinned Python toolchain

ST-0102 pins CPython 3.14.6, uv 0.12.1, Ruff 0.16.1, mypy 2.3.0, and pytest
9.1.1. `pyproject.toml` owns project/static-tool configuration, `uv.toml` owns
uv's resolution/install configuration, and `uv.lock` is the unaltered
uv-generated dependency lock. The root is currently a virtual uv project:
`python/raos` is the production source boundary, but packaging and product
dependencies are added only by their owning Stories.

Install the exact uv binary through an independently checksum-verified release
artifact, then use the repository commands:

```bash
scripts/python_toolchain.sh --uv /absolute/path/to/uv install
scripts/python_toolchain.sh --uv /absolute/path/to/uv sync
scripts/python_toolchain.sh --uv /absolute/path/to/uv check
```

The wrapper requires an absolute uv executable path, verifies uv 0.12.1 before
invoking a fixed Make target, and removes GNU Make's inherited pre-parse control
inputs. It requires Linux `/bin/bash` and uses privileged startup mode so
`BASH_ENV`, inherited shell options, and exported functions cannot run before
its validation. `install` is the explicit managed-interpreter download step.
Normal sync requires that interpreter to exist, rejects a stale lock, and
disables implicit Python downloads. The general Python-toolchain check targets
run the locked `python-sync` prerequisite once; ST-0104/ST-0105 read-only
contract gates instead require a previously hydrated environment and run
offline with no cache or synchronization.
`scripts/python_toolchain.sh --uv /absolute/path/to/uv lock` is the intentional
lock-regeneration operation; review and commit the complete generated
`uv.lock` after it runs.
After one successful online sync has hydrated the current platform cache,
Wrapper command `sync-offline` recreates the fixed, repository-local
`.venv-offline-check` environment and proves it can be synchronized with
network access disabled. It rejects a symlink at that managed path and is not
a cold-install substitute.
The configured source is the Python Package Index, and the commands clear uv
config, source, resolution, hash-verification, interpreter, and dependency-group
override variables before locking or installation. It also removes Python and
pytest injection variables, disables uv dotenv loading, and does not honor an
ambient environment destination. Every Make command supplies the absolute
repository `uv.toml` as uv's sole configuration file, disabling automatic user
and system configuration discovery. The evidence wrapper removes inherited
`MAKEFILES`, `MAKEFLAGS`, and `GNUMAKEFLAGS`; the Makefile additionally rejects
preloaded makefiles, direct `MAKEFLAGS` assignments, and GNU Make's
environment-override, ignore-error, dry-run, and touch modes because those
modes cannot produce verification evidence. Parallel make remains supported.
Direct Make commands remain developer conveniences, while recorded
verification must use the wrapper. Do not use `--frozen` as a substitute for
`uv lock --check`: frozen mode trusts the existing lock and does not prove it
matches `pyproject.toml`.

The local Python check runs Ruff lint, a format check limited to maintained
Python source/tests, strict mypy on maintained `python/raos` source, and the
isolated ST-0102 suite. Externally generated ST-0105 Pydantic modules are not
reformatted or treated as hand-maintained mypy/Pyright source; their exact
inventory, imports, Pydantic schema construction, and source regeneration are
verified by the ST-0105 gate. Base CI and its supported operating-system matrix
remain ST-0106 scope.

## Pinned Node toolchain

ST-0103 pins Node 24.18.1 LTS and its bundled npm 11.16.0. The private root npm
workspace contains `apps/web`, the ST-0105 generated `packages/web-contracts`
package, and `packages/web-ui`.
`apps/web/package.json` pins Next.js 16.2.12, React 19.2.8, and React DOM
19.2.8; no application route, component, or server is created by this Story.
Root development tools pin TypeScript 6.0.3, ESLint 9.39.5 with the matching
Next.js flat config, Prettier 3.9.6, Vitest 4.1.10, Vite 8.2.0, and Pyright
1.1.411. Exact transitive overrides keep PostCSS at 8.5.25 and Sharp at 0.35.3
because Next.js 16.2.12 still declares advisory-affected releases. The
implementation-time official-source and advisory record is
`docs/architecture/ST-0103-toolchain-snapshot.yaml`.

Use independently checksum-verified Node and its bundled npm CLI through the
recorded-evidence wrapper:

```bash
scripts/node_toolchain.sh \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js sync
scripts/node_toolchain.sh \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js check
```

The wrapper requires both absolute paths and verifies Node 24.18.1 and npm
11.16.0 before invoking a fixed repository target. It uses Linux
`/bin/bash -p`, clears shell/Node/npm/GNU Make pre-parse inputs, disables
Corepack network use and Next.js telemetry, and fixes npm's registry,
configuration, cache, and install behavior. Dependency lifecycle scripts are
disabled. Direct npm and Make commands are developer conveniences; recorded
verification uses the wrapper.

`sync` uses `npm ci`, so its deletion scope is the fixed root `node_modules`
tree plus any `node_modules` tree below the three allowlisted workspaces. Before
npm runs, the gate rejects symlinks at the cache, every deletion target, each
workspace parent, and each fixed package input. It fails when `package.json`
and `package-lock.json` disagree and never updates the lock. Run it only as a
single-process repository maintenance command without a concurrent same-UID
Node workspace mutator. The intentional lock-regeneration operation is:

```bash
scripts/node_toolchain.sh \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js lock
```

Review and commit the complete npm-generated `package-lock.json`; never edit it
by hand. After an online `sync` hydrates the fixed cache, wrapper command
`sync-offline` installs into a fresh temporary workspace with npm network access
disabled and compares the normalized installed dependency tree with the online
tree. This is a same-platform warm-cache reproduction proof, not a cold or
cross-platform install claim.

The Node `check` command performs the locked sync, exact version gate, complete
`npm ls --all` dependency-tree validation, check-only formatting, Next.js
ESLint, strict TypeScript, Pyright, and the isolated ST-0103 Vitest suite. It
does not run a Next.js build because product routes and components belong to
later Stories.

## Generated contract types and clients

ST-0105 deterministically projects the verified
`contracts/raos-v0.4/contract-repository.v0.4.json` repository into Pydantic v2
models under `python/raos/generated` and TypeScript schema types plus separate
Public/Admin/Internal OpenAPI clients under
`packages/web-contracts/src/generated`. It also generates a typed AsyncAPI
registry; no broker, HTTP handler, runtime Content AST policy validator, or
deployment is activated. Generated files identify their source and command and
must not be edited by hand.

Use the combined recorded-evidence wrapper with independently verified exact
uv, Node, and bundled npm paths:

```bash
scripts/codegen_toolchain.sh \
  --uv /absolute/path/to/uv \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js hydrate
scripts/codegen_toolchain.sh \
  --uv /absolute/path/to/uv \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js install
scripts/codegen_toolchain.sh \
  --uv /absolute/path/to/uv \
  --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js gate
```

`hydrate` is the explicit environment mutation: it synchronizes the locked
`.venv`, `node_modules`, and local package caches and must be run separately.
`install` then mutates only the two generated roots plus
`changes/st-0105/manifest.json`. It publishes a durable write-ahead journal
before either tree changes; a later `install` automatically rolls a
pre-commit interruption back or finishes committed cleanup. Terminal journals
are atomically renamed to `.install-transaction.v1.cleanup` before their
contents are removed, so cleanup interrupted at any entry is retried without
parsing a partial journal. Do not delete a pending transaction directory by
hand. Every managed ancestor is opened from the physical repository root with
`O_NOFOLLOW`, and all publish, fsync, recovery, and cleanup operations use
pinned directory descriptors.

Before recovery, the wrapper runs only pending-tolerant storage guards: the
repository `.venv`, Node storage roots, and required package metadata must be
real local entries. Recovery then runs before exact tool-version validation.
The generator independently opens every ancestor of the datamodel, Node,
OpenAPI, and TypeScript entrypoints from the filesystem root with
`O_NOFOLLOW`, so an ancestor symlink cannot redirect executable code.

`check`, `test`, `typecheck`, and `gate` require the hydrated exact environment
and run offline/no-cache/no-sync. They neither invoke `uv sync` nor `npm ci`;
`check` regenerates privately and compares complete bytes without writing. A
pending recovery makes a read-only operation fail and instructs the operator
to run `install`. The
`contract-codegen-gate` Make target first revalidates the complete ST-0104
repository, then checks two-generation determinism, exact hashes and no extra
files, all 224 Python bindings, all 185 separated HTTP operations, the
105-message AsyncAPI registry, rollback behavior, isolated-wrapper recovery,
and TypeScript compilation. The wrapper recovery integration uses a disposable
temporary repository; read-only gates never replace the real generated roots
or manifest.
The generated fetch client inherits the strict root TypeScript configuration;
only `exactOptionalPropertyTypes` is disabled in this isolated generated
package because the pinned external generator emits optional property
assignments that are not compatible with that flag.

The local suite is a TST-004 implementation equivalent, not formal CI
evidence. Canonical effective status remains `NOT_STARTED`, verification stays
`NOT_EXECUTED`, and base CI execution remains ST-0106 scope.

## Design and verification

Start with `docs/README.md`, then follow the selected Story's canonical read
order and the root `AGENTS.md`. Verify the imported package independently:

```bash
python3 scripts/import_raos_design.py verify
```

Story tests run in separate pytest processes because suite-local module names
overlap. The current local Story checks include:

```bash
uv run --locked --no-sync pytest -q tests/st0101
scripts/python_toolchain.sh --uv /absolute/path/to/uv test
scripts/node_toolchain.sh --node /absolute/path/to/node \
  --npm-cli /absolute/path/to/npm-cli.js test
scripts/python_toolchain.sh --uv /absolute/path/to/uv contract-gate
```

Those local results are not formal TST-001/TST-005 CI evidence. The local
ST-0103 result is likewise not formal TST-006 CI evidence, and the local
ST-0104 gate is not formal TST-002 CI evidence. Base CI is deferred to ST-0106,
PR governance to ST-0107, and runnable local services to ST-0201 and later
Stories. A local
temporary Git repository can verify clean-clone mechanics, but local bootstrap
alone does not prove the delivered repository's tracked-file set, a hosted
remote clone, pull request, or CI run. Those require separate evidence.

## Safety boundaries

- Never edit `zip/**`, `docs/canonical/**`, `docs/upstream/**`, or
  `docs/manifest.json`.
- Never commit credentials, production data, review bodies, raw prompts, or
  personal data.
- Publishing, production changes, policy activation, and release decisions
  remain human-approved actions.
