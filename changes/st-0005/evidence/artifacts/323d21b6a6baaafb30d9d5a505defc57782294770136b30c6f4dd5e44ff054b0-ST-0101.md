## Implementation

`workspace-layout.json` now owns an exact, sorted allowlist of 42 inert leaf
directories across `apps`, `packages`, `contracts`, `python/raos`, `prompts`,
`policies`, `schemas`, `migrations`, `infra`, `tests`, and `docs`. The
standard-library `scripts/bootstrap_workspace.py` validates that closed
contract, materializes only missing generated markers, and verifies drift in a
no-write mode. `Makefile` exposes `bootstrap` and `check-workspace`; the root
README, AGENTS, ignore policy, and generated leaf README files document the
reserved boundaries without claiming downstream functionality.

The bootstrap performs bounded regular-file reads, strict duplicate-key JSON
loading, normalized allowlisted path validation, descriptor-relative
`O_NOFOLLOW` traversal, preflight/write-phase inode comparison for existing
directories, exclusive final-leaf creation for preflight-missing directories,
and final root/directory/marker identity checks. It never replaces an existing
marker and rejects unmanaged, drifted, non-regular, symlinked, oversized, or
multiply hard-linked markers.

Missing markers are written completely to an anonymous Linux `O_TMPFILE`,
fsynced, published create-if-absent through `/proc/self/fd`, checked for exact
descriptor/path inode identity and single-link state, and followed by a
directory fsync. During that window the single-threaded process uses
`PR_SET_DUMPABLE=0` so another same-UID process cannot acquire the anonymous
descriptor through procfs; the original dumpability state is restored on both
success and exception paths. Unsupported `O_TMPFILE`, `prctl`, or procfs
publication fails closed with no named-temp fallback. Read-only `--check` does
not need those write-only capabilities.

An independent race review first found discarded preflight directory identity
and a replaceable named temporary path. A nested review then demonstrated the
same-UID `/proc/<pid>/fd` hard-link window. The implementation and deterministic
tests were extended for those findings, ordinary-directory replacement,
missing-leaf insertion, destination appearance, regular-file/FIFO swaps,
persistent and publication-time hard links, unsupported anonymous-file/procfs
environments, and parent/child procfs isolation. The independent review also
ran repeated normal/error-path descriptor-count probes without finding a leak.
Its final security verdict was PASS with no blocker under the explicit Unix
boundary below.

An actor with the same UID and arbitrary rename/write access to the repository
is not treated as a security boundary: that actor can mutate the workspace
directly. Bootstrap must not run concurrently with an adversarial same-UID tree
mutator. A directory moved after its descriptor is opened can retain a marker
on that pinned inode before final logical-path validation reports failure. This
limitation and all Linux write prerequisites are stated in the root README,
AGENTS, and ExecPlan.
