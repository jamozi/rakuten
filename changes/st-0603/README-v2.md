# ST-0603 maximum-safe local Fact-conflict runtime V2

This additive V2 implements the locally executable portion of Canonical Story
`ST-0603`. The predecessor V1 reference plan remains a non-executable historical
record. Its bytes and semantics are not reused as runtime authority.

## Exact input and comparison boundary

The only accepted input is a non-empty tuple of exact
`PersistedFactExtractionV2` records from ST-0602. Every source binding, command,
Fact, validation record, batch, outbox event, persisted chain, canonical mapping,
and zero action count is revalidated before comparison. The scan command binds
the exact persisted-record hash, batch hash, chain hash, source snapshot, and
each Fact hash. Input order is canonicalized and an exact repeated batch is
idempotently deduplicated; the same batch ID with different bytes fails closed.

A comparison is made only when `subject_type`, `subject_id`, and `predicate` are
exactly equal. Validity windows are half-open. A touching boundary is disjoint.
Compatible unit and locale values are compared exactly by typed numeric or
boolean value. There is no tolerance. Exact equal values create no conflict and
disjoint windows create no conflict. Differing compatible values create an
unresolved record. An incompatible unit or locale is explicitly routed to an
unresolved review record without conversion.

Every emitted conflict and queue record remains `UNRESOLVED`, `HUMAN_REVIEW`,
and `NOT_READY`. Content policy is exactly `source_conflict`, with
`silent_resolution_forbidden: true`. Winner, tolerance, resolution, assignment,
and authority priority remain absent. Conflict identity is bound to the complete
deterministic scan so a repeated pair in a different input set cannot collide
with an earlier append.

## Durable owner-private boundary

`OwnerPrivateSqliteFactConflictStoreV2` is limited to `ENV-DEV` and `ENV-CI`.
It creates only the fixed `st0603-fact-conflicts.sqlite3` file inside an exact
owner-private `0700` directory. Initialization is allowed only after the file is
created with `O_EXCL`; a pre-existing empty, partial, foreign, symlinked,
hard-linked, or non-`0600` database is rejected.

The adapter pins directory-entry device and inode identity through a directory
descriptor and `O_NOFOLLOW`, verifies the exact STRICT/FK schema, trigger and
auto-index inventory, decodes canonical JSON with duplicate-key and size/depth
limits, reconstructs every UUID/RFC3339/typed record, recomputes every payload
and chain hash, and checks all cross-table links and counts. Conflict rows,
review-queue rows, the undelivered local outbox event, journal result, and state
CAS are one SQLite transaction. Update and delete triggers keep all records
append-only.

Known pre-commit failure is reported as a known rollback. An ambiguous commit is
never reported as a rollback: the application performs exact durable recovery,
returns `RECOVERED_COMMIT` only when the complete expected result is present, and
otherwise returns `COMMIT_UNKNOWN`. Head, count, and the previously observed
chain prefix are process-lifetime monotonic. No cross-restart rollback-detection
claim is made because no independent durable anchor exists.

## Deliberately absent authority

This Story has no winner selection, conflict resolution, actor assignment,
Unknown or Claim creation, ranking, recommendation, arbitrary URL or HTML,
publication, provider, network, credential, browser, AI, delivery, staging,
release, or Production capability. Affiliate rate, commission, EPC, RPM,
revenue, reward, and profit are not runtime inputs. External, provider,
publication, and AI action counts are exact integer zero before and after every
collaborator boundary.

The recorded synthetic fixture is disabled and contains no credential, raw
provider text, or URL. Local TST-007/TST-020 analogs do not constitute formal
suite, live-provider, hosted-CI, staging, release, or Production evidence.

## Local verification

The V2 owner generator is:

```text
python scripts/build_st0603_fact_conflict_runtime.py
python scripts/build_st0603_fact_conflict_runtime.py --check
```

The focused suite is kept separate from V1 and uses unique module basenames:

```text
pytest -q tests/st0603/test_st0603_fact_conflict_domain_v2.py
pytest -q tests/st0603/test_st0603_fact_conflict_sqlite_v2.py
pytest -q tests/st0603/test_st0603_fact_conflict_hostile_v2.py
pytest -q tests/st0603/test_st0603_fact_conflict_generator_v2.py
```

The generated V2 manifest binds the exact ST-0602 predecessor commit and
runtime artifacts, Canonical sources, V2 runtime, tests, documentation,
contract, fixture, and generator. `--check` is a no-write comparison against the
deterministic output. The legacy V1 generator remains the sole owner of V1
generated bytes and its predecessor binding.
