# ST-1906 implementation work log

## Preflight

- Objective: add the maximum-safe local interface for advanced causal
  attribution while preserving `DEFERRED_POST_MVP` and a separate release
  decision.
- Sources reviewed: Canonical precedence/decisions/open decisions, ST-1906,
  dependency ST-1303, analytics attribution/event/KPI design, security/privacy
  design plus data/control/threat catalogs, and TST-032 acceptance design.
- Safe assumptions: only a pre-registered aggregate randomized two-arm method
  is represented; synthetic privacy review evidence has no live authority;
  insufficient evidence is unavailable; no observational identity inference or
  Provider-total allocation is attempted.
- Planned files: ST-1906 contract/fixture/generated artifacts/completion,
  domain/application/port/recorded adapter, owner generator and focused tests.
- Tests: deterministic estimator and generation, disabled/nonlocal paths,
  privacy/signal/maturity/program/period/zero handling, hostile parsing,
  replay/concurrency, dependency regression, Ruff, strict mypy, compile,
  sensitive-term scan and diff check.
- Out of scope: credentials, personal or Production data, live provider or
  tracking, persistence, formal TST-032, publication, staging, release and
  Production.

## Implementation notes

- The local seam is disabled by default and callable only in ENV-DEV/CI.
- The input is one caller-owned byte string; the adapter has no path, URL,
  provider SDK, environment lookup, network or persistence capability.
- Privacy and sufficient-signal gates are executable domain rules. Unsafe but
  well-formed evidence returns a closed unavailable reason and no estimate;
  malformed or authority-bearing input is refused.
- The output is a non-authoritative analysis candidate. All automated content,
  recommendation, tracking, publication and operational writes remain
  structurally impossible.
