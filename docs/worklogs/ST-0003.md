### Ambiguities and safe decisions

- ST-0003 consumes v0.2 and never regenerates from v0.1.
- `FAILED→FAILED_TERMINAL` and `PENDING→REQUESTED` are the only automatic AI
  Job mappings. Predecessor `BLOCKED` is terminal but adopted
  `AWAITING_HUMAN` is non-terminal, so unresolved rows remain visible and
  block Contract until an operator classifies them from evidence.
- Prompt `REJECTED` is not silently collapsed into `RETIRED`; it receives the
  same explicit-classification checkpoint.
- Under-specified proposal API/event payloads are completed with strict
  internal metadata schemas only; no raw prompt/input/output is exposed.
- The event delta is deliberately limited to evaluation completion v2 and
  release approval/revocation v1; dataset lock and evaluation request remain
  commands plus audit actions until consumers are specified.
- AI-001–AI-008 keep their existing idempotency/concurrency semantics.
  Required `If-Match` is applied only to new mutable governance transitions;
  adding it to legacy AI-004 in place would violate the compatibility policy.
- Release Decision carries direct resolved-model, policy, dataset, evaluation,
  and code-SHA bindings; `APPROVED_ACTIVE` must follow a bounded
  `APPROVED_CANARY` transition rather than bypassing canary evidence.
- Portable JSON Schema files are this story's generated types. Python and
  TypeScript generation stays deferred to ST-0105.
