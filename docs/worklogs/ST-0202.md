## Hosted failure diagnosis

- The hosted runner reported Docker Compose `2.38.2` and Docker Engine
  `28.0.4`. Compose passes its normalized `published` value directly to the
  Engine `HostPort`; omitting the field leaves that value empty for Engine
  assignment:
  <https://github.com/docker/compose/blob/v2.38.2/pkg/compose/create.go#L781-L790>.
- The Compose ports specification permits an omitted host port and requires an
  unassigned host port in that case:
  <https://compose-spec.github.io/compose-spec/05-services.html#ports>.
- Moby `28.0.4` skips external-connectivity programming for an internal
  network endpoint, which is why omitted, bounded-range, and explicit-zero
  publication shapes all reached Healthy without a host mapping:
  <https://github.com/moby/moby/blob/v28.0.4/libnetwork/endpoint.go#L698-L707>.
- A non-internal bridge still programs port mappings when its
  `enable_ip_masquerade` option is false; that option gates network-level
  source NAT, not per-port binding:
  <https://github.com/moby/moby/blob/v28.0.4/libnetwork/drivers/bridge/bridge_linux.go#L1506-L1544>
  and
  <https://github.com/moby/moby/blob/v28.0.4/libnetwork/drivers/bridge/setup_ip_tables_linux.go#L416-L465>.
- Docker documents loopback host publication and bridge driver options here:
  <https://docs.docker.com/engine/network/port-publishing/> and
  <https://docs.docker.com/engine/network/drivers/bridge/#options>.
- Compose documents that `init: true` runs a platform-specific init as PID 1:
  <https://docs.docker.com/reference/compose-file/services/#init>. Moby
  `28.0.4` installs that process at `/sbin/docker-init` ahead of the configured
  entrypoint:
  <https://github.com/moby/moby/blob/v28.0.4/daemon/oci_linux.go#L725-L743>.
- The pinned SeaweedFS entrypoint recursively `exec`s through `su-exec seaweed`
  and then `exec`s `/usr/bin/weed`; it does not replace Docker init at PID 1:
  <https://github.com/seaweedfs/seaweedfs/blob/1355c7a102194d6c461baf090eff50367b575afb/docker/entrypoint.sh>.

## Status boundary

Local implementation artifacts do not alter the effective canonical
`NOT_STARTED / NOT_EXECUTED` status. No production storage, remote Docker
engine, anonymous S3 access, raw credential environment value, retention period,
lifecycle-delete rule, runtime fixture result, vulnerability result, or formal
TST-014 result is asserted by this worklog.

The 2026-08-15 V5 hosted-compatibility correction keeps the root Compose bytes
and persistent interface unchanged. Exact Compose v2.38.2 and Moby v28.0.4
source inspection explains all three failed port shapes: Compose passes the
publication request through, while Docker Engine deliberately omits external-
connectivity programming for an internal endpoint. The repaired disposable
override therefore omits `published`, retains the internal bridge, and adds
one project-scoped non-internal bridge with source NAT disabled solely so the
Engine can create the loopback mapping. Disabled masquerading reduces egress;
it does not claim the complete isolation of an internal network. The exact
normalized port and network model is rejected before container creation and
every project Compose use unless the complete shape survives.

The ST-0107 manifest changes only because it inventories the modified wrapper
and generator; governance semantic artifacts remain byte-identical. Named
downstream pins and manifests are regenerated only to close current/live
provenance, while their runtime and business semantics remain unchanged. A new
hosted `Storage` job on the exact future commit remains required to establish
that Docker Engine selects and reports one available loopback port within
`1024..65535`. Persistent commands remain internal-only and byte-equivalent as
required; because Moby 28 suppresses port programming for that shape, their
mapping compatibility is a known `NOT_EXECUTED` boundary rather than a runtime
claim.

The 2026-08-15 V6 correction preserves the exact image, Compose bytes, port and
network behavior, secret transport, and OD-014 boundary. Hosted V5 proved the
disposable Engine-assigned loopback mapping and reached Healthy; it did not
prove the later runtime or authenticated checks. The repaired assertion keeps
Docker init as root PID 1 and verifies the privilege-dropped SeaweedFS service
as its sole direct child using a closed, non-logging container-`/proc` probe.
A new hosted Storage job on the exact future commit remains required to prove
that topology check, exact version, authenticated fixture, and cleanup.
