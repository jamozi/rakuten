  from one identity-checked root descriptor with no-follow directory opens.
  Root, ancestor, and leaf path/descriptor identities bind device, inode,
  mode, link count, size, mtime, and ctime before and after the bounded read.
  Files must be regular and single-linked; the reader consumes the exact
  captured size plus one bounded probe byte and requires nonzero

## 2026-08-06 generated-output installer hardening

- The generator's two allowlisted output publications now start at the
  filesystem root and open every repository and output-parent component
  descriptor-relatively. Directory and staging opens require nonzero
  `O_DIRECTORY`, `O_NOFOLLOW`, and `O_CLOEXEC` support as applicable. Missing
  owned output directories are created only by basename with `dir_fd`, and
  the parent that gains each entry is fsynced before traversal continues.
- Directory device/inode/mode bindings are checked before and after opening
  and again after publication. An existing output must be absent or a regular
  single-linked file; its full metadata signature is captured before staging
  and rechecked immediately before the same-parent replacement.
- Each staging leaf is created exclusively with mode `0600`, written fully,
  changed to exact mode `0644`, checked as regular, single-linked, and exact
  size, and fsynced while its descriptor remains open. After replacement, the
  still-open staging descriptor and installed pathname must identify the same
  inode and metadata, and the staging pathname must be absent. The output
  parent is then fsynced before all directory bindings are revalidated.
- Failure cleanup attempts the staging unlink and parent fsync before closing
  every acquired descriptor once in reverse order. An `OSError` is reduced to
  a stable diagnostic; cleanup cannot replace a primary failure and adds only
  one sanitized note. A cleanup-only failure raises a stable `RuntimeError`.
- The compact installer matrix passed 17 focused cases: fresh directory
  creation and continuous `dir_fd` traversal, required flags and fsyncs,
  ancestor symlink and pre/post-open swaps, target symlink/FIFO/hardlink and
  precommit mutation, staged-inode postcheck, write/replace cleanup, and
  once-only close/unlink failure handling with primary-error preservation.
  The broader generation run passed 49 tests with only the two deliberately
  stale-output checks deselected; after an intermediate regeneration, the
  complete isolated Story suite passed 105 tests.
- Publication remains deliberately non-transactional under current ST-0701
  authority. There is no lock, journal, rollback protocol, or atomic
  two-output commit. The generator still publishes the registry first and the
  manifest last, so a concurrent generator or crash can leave a mixed pair;
  deterministic `--check` fails closed on that mismatch for operator repair.
  ST-0104 `ContractRepository` and the runtime adapter are unchanged by this
  increment.
- This append-only entry is finalized before the required final
  registry-then-manifest regeneration. Formal TST-001/TST-017, hosted CI,
  human/security review, canonical status apply, provider validation,
  staging, release, and production remain `NOT_EXECUTED`.
