## Implementation

The repository now has an exact Python tooling contract:

- `.python-version` and `project.requires-python` both require CPython 3.14.6;
- `uv.toml` requires uv 0.12.1 and is passed by absolute, quoted path as the
  sole general uv configuration, so user/system uv configuration is not
  discovered;
- `pyproject.toml` keeps uv's project-only metadata in its required location,
  declares a virtual project and the default `dev` group, and pins every direct
  development dependency exactly;
- Ruff 0.16.1, mypy 2.3.0 in strict mode, and pytest 9.1.1 with ambient plugin
  autoload disabled are configured as repository gates; and
- the unedited uv-generated `uv.lock` contains 21 package rows, installs 19
  distributions, uses only the configured PyPI registry, includes SHA-256 for
  every artifact, and has SHA-256
  `72474fd1f3b6def7d66e08c382d3319c34fc76a7607b9d158b4db2a03b52bd46`.

The Make targets separate the explicit interpreter download and mutable lock
generation commands from locked sync/check operations. They clear ambient uv,
Python, pytest, and mypy inputs that can change the contract or create a false
PASS. Internal helpers and repository paths cannot be replaced through Make
variables; paths are derived from the loaded Makefile and quoted, including in
workspace paths containing spaces. A fresh offline proof recreates only the
fixed `.venv-offline-check` path, rejects a symlink there, performs the lock
check with network disabled, and synchronizes without Python downloads.

GNU Make processes some inputs before a repository Makefile can defend itself.
Therefore `scripts/python_toolchain.sh --uv ABSOLUTE_PATH COMMAND` is the
recorded-evidence entrypoint. It requires a regular executable at an absolute
path, uses Linux `/bin/bash -p` to suppress startup files/options/functions,
verifies uv 0.12.1, accepts only a fixed command vocabulary, removes inherited
shell and Make pre-parse controls, and then invokes the repository Makefile.
Direct Make remains a trusted developer convenience and rejects common non-
verifying modes, direct `MAKEFLAGS`, and preloaded `MAKEFILES`.

## 2026-08-15 hosted cold-cache test portability repair

### Preflight

### Diagnosis

GitHub-hosted Unit hydration intentionally uses uv `--no-cache`. The old
`hydrated_uv_cache()` probe treated a successful offline `uv lock --check` on
the unchanged project as proof that dependency metadata and wheels were
cached. That command needs neither capability when the committed lock is
current. Consequently, drift-resolution, Make-injection, fresh-offline-sync,
and the nested Make test ran against a cold cache and failed with uv's exact
offline resolution or artifact cache-miss diagnostics instead of testing their
intended invariant.

### Change

The test helper now reports only whether uv's local cache directory exists and
makes no hydration claim. Each cache-dependent operation executes first, then
skips only for one of two closed uv 0.12.1 diagnostic conjunctions: offline
dependency resolution unavailable from cache, or a failed locked-wheel fetch
whose requested `files.pythonhosted.org` artifact is absent from cache. A zero
exit, an incomplete or near-match message, a different artifact origin, or any
ordinary lock/Make/assertion failure cannot select the skip. When the cache is
hydrated, all existing drift, injection-removal, offline-environment, and exact
inventory assertions still execute unchanged. New regression cases exercise a
real empty-cache drift resolution, the locked-wheel diagnostic, and four
near-miss/zero-exit refusals.
