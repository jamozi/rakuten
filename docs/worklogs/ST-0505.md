# ST-0505 worklog — bounded live Rakuten smoke implementation

## Scope

This candidate adds a disabled-by-default, staging-only executable boundary for
canonical ST-0505. It does not modify the ST-0502 recorded-only contract, the
existing ST-0505 reference plan, Canonical status, OD-015, TST-016 execution
status, credentials, provider state, publication, release, or Production.

## Official provider contract

The request shape is pinned to the Rakuten Ichiba Item Search API version
2026-07-01 documentation retrieved on 2026-08-18:

- origin `https://openapi.rakuten.co.jp`;
- path `/ichibams/api/IchibaItem/Search/20260701`;
- App ID only in the required `applicationId` query parameter;
- Access Key only in the `accessKey` request header;
- JSON `formatVersion=2`, page 1, one hit, standard sort, and a fixed five-field
  output allowlist.

Affiliate ID, callback, retry, pagination, background execution, storage,
persistence, and publication are absent.

## Authorization and credential boundary

The runner has no default authorizer and no credential reader. A caller must
inject:

1. an external one-shot authorizer that validates and atomically consumes the
   exact grant SHA-256; and
2. a fixed-alias credential source for `rakuten_application_id` and
   `rakuten_access_key`.

The grant binds the request hash, distinct Operations-evidence and execution-
approval hashes, staging environment, issue time, and expiry. Its lifetime is at
most 15 minutes. The repository does not provide a permissive authorizer and
does not interpret a syntactically valid digest as approval. Trust verification
and durable one-shot consumption remain responsibilities of later approved
Operations composition.

Credential, request, grant, raw-response, and failure displays are redacted.
Credential/request/grant/raw-response generic serialization is rejected. No CLI
or process-environment credential loader is included.

## Network and response boundary

The default transport performs at most one HTTPS GET with the system trust
store, TLS 1.2 minimum, proxy inheritance disabled, redirects denied, fixed
origin/path/query/header shapes, five-second timeout, and a 256 KiB body cap.
It rejects Access Key or Affiliate ID in the query, non-string coercion,
Content-Length mismatch, oversized bodies, and any second attempt.

Only a closed set of response headers is retained in a private raw-response
object. Raw provider bytes and headers have no public accessor and cannot be
pickled. UTF-8, JSON duplicate keys, non-finite values, depth, node count,
content type/encoding, response fields, values, item URLs, request IDs, and rate
metadata are validated fail closed.

Success returns a validated sanitized receipt containing only hashes, bounded
observations, provider request ID when safe, and exact action counts. Receipt
construction rejects forged status, rate, pagination, retry, storage,
persistence, or publication values.
