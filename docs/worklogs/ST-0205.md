## Implementation notes

- Exact 13-domain order: ops, iam, portfolio, catalog, evidence, editorial,
  ai, policy, publishing, freshness, analytics, finance, readmodel.
- The versioned bundle has reviewed Time/Currency/Locale/Unicode/Large-value/
  DST/JST/duplicate/out-of-order scenarios.
- Payload keys are reconstructed in canonical allowlist order before output;
  serialized JSON key ordering is deterministic and not a security boundary.
- Structural forbidden-key checks normalize NFKC, camel-case boundaries, and
  separators. Canonical privacy metric names such as `review_count`,
  `email_verified`, and policy text `NO_REVIEW_BODY` are not substring-blocked.
- Secret checks reuse the repository scanner and error messages never include
  input canaries. Valid IPv4 and IPv6 literals are rejected using the standard
  library parser; invalid dotted/version strings are not treated as addresses.
- Missing classification normalizes to CONFIDENTIAL. Explicit RESTRICTED data
  gets a distinct fail-closed rejection; arbitrary unknown classes fail as
  unknown.

## 2026-08-06 descriptor-relative read hardening

- Replaced validate-path-then-reopen source, pinned-input, contract, and output
  reads with one bounded descriptor-relative capture below the opened repository
  root. Directory and file opens require `O_DIRECTORY`, `O_NOFOLLOW`,
  `O_NONBLOCK`, and `O_CLOEXEC` as applicable and fail closed if a required
  platform flag is unavailable.
- The capture binds path-before, opened-before, opened-after, and path-after
  metadata, including device, inode, mode, link count, size, mtime, and ctime.
  Files must be regular, single-linked, and no larger than the fixed 8 MiB hard
  limit. Digest checks, license JSON parsing, contract YAML parsing, manifest
  hashing, output-mode checks, and output comparisons reuse those exact bytes
  and metadata without a pathname reopen.
- Deterministic adversarial tests cover repository-root, ancestor, and target
  replacement; symlink, FIFO, and hardlink rejection; same-inode same-size,
  truncation, and extension changes; exact and over-limit sizes; short and
  failed reads; missing filesystem safety flags; descriptor cleanup failures;
  capture reuse; and a mutation-free `--check` path.
- Pinned uv 0.12.1 offline/locked/no-sync verification passed: generator
  `--check`, 110 isolated ST-0205 tests, targeted Ruff lint and format check,
  and scoped `git diff --check`.
- These results remain local implementation-candidate evidence only. Formal
  TST-005/TST-031, hosted CI, privacy/security owner review, staging,

## 2026-08-06 YAML size-bound audit remediation

- Independent review found that the secure repository reader's generic 8 MiB
  hard limit had unintentionally widened the ST-0205 contract loader's prior
  2 MiB YAML limit. The contract now uses `shared.MAX_YAML_BYTES` during its
  descriptor-relative capture, and the bytes-only YAML loader independently
  enforces the same limit before decoding, scanning, or parsing.
- Regression coverage proves that an exactly 2 MiB valid YAML document reaches
  the parser, while a syntactically valid comment-padded document above 2 MiB
  is rejected both at the contract capture boundary and defensively by the
  bytes parser before YAML processing.
- Pinned uv 0.12.1 offline/locked/no-sync/no-cache verification passed after
  remediation: generator `--check`, 112 isolated ST-0205 tests, targeted Ruff
  lint and format check, and scoped `git diff --check`.
- Formal TST-005/TST-031, hosted CI, privacy/security owner review, staging,
  production, retention approval, and canonical status APPLY remain
  unexecuted.
