## Implemented execution boundary

- GitHub setup/checkout and source-constrained locked dependency hydration are
  the explicit network-enabled phase. Setup action caches are disabled.
- Before hydration, `scripts/validate_ci_hydration.py` runs inside the denied
  network/PID boundary and validates exact pins, approved origins, hashes, lock
  formats, workspace manifests, and npm configuration. Its npm checks use a
  positive ASCII semver grammar, require exact root/workspace and nearest
  transitive closure, verify captured versions against effective ranges, and
  allow an absent peer only with exact optional metadata. The reviewed ST-0103
  overrides are closed and substituted explicitly. No descendant of that
  preflight survives its PID namespace.
- After exact Node setup, bundled npm runs `ci --dry-run --offline` under the
  denied-network guard against a disposable metadata-only copy, fresh empty
  cache, and clean config. This checks npm's own peer/override/range semantics
  before real hydration. It must preserve the copied lock hash and leave no
  `node_modules` path.
- The hydration step directly invokes the pinned `uv`, Node, and npm tools with
  fixed registries and clean environments. It ignores uv source/config
  overrides, refuses Python builds, disables npm lifecycle scripts, and invokes
  no repository Make target or wrapper while network is enabled.
- `scripts/ci_job.sh` never hydrates. GitHub Actions starts it inside
  `scripts/run_network_denied.sh`; a local direct invocation enters that guard
  itself after the operator runs `make ci-hydrate`.
- The network guard rejects a root caller and sockets on standard descriptors,
  closes every other inherited descriptor, maps the current non-root identity,
  and uses fresh Linux user, network, and PID namespaces. It starts
  `scripts/assert_network_denied.py` before the requested command; the
  assertion fails closed unless both namespaces are distinct from the parents,
  the entry process is PID 1, the identity remains non-root, only loopback is
  present, and IPv4/IPv6 external routes are unavailable. An inherited
  `no_new_privs` seccomp filter denies network socket creation and connection,
  host pathname Unix sockets, and io_uring bypasses; local `socketpair` remains
  available for tool signalling. Each Make target repeats the assertion.
- The full worktree-and-history secret scan runs through the same guard. Its
  exact local equivalent is:

  ```bash
  scripts/run_network_denied.sh --home "$HOME" -- \
    /usr/bin/python3 -I scripts/scan_secrets.py --worktree --git-history
  ```

  A direct `python3 -I scripts/scan_secrets.py --worktree` run remains a
  diagnostic for source exports and is not equivalent evidence.

## Audit-driven remediations

- Removed repository-controlled Make/script execution from the
  network-enabled hydration step and replaced it with fixed direct `uv`/npm
  commands plus a denied-network metadata preflight.
- Closed inherited descriptors, rejected socket-backed descriptors 0–2,
  blocked pathname Unix-socket/DNS proxy access, and added a killed PID
  namespace so pre-hydration descendants cannot bridge phases.
- Replaced substring-based generic-secret placeholder suppression with an
  anchored whole-value policy. Strong values containing words such as
  `example`, `fake`, `sample`, or `fixture` are now detected and remain
  redacted in output.
- Replaced a negative npm descriptor blacklist with a positive semver grammar,
  nearest captured-entry and effective-version checks, root/workspace closure,
  and an explicit optional-peer exemption. This closes independently reproduced
  Git/SSH specifier, missing required peer, incompatible captured version, and
  missing direct dependency resolution paths.
- Added the exact bundled-npm empty-cache offline dry-run as a semantic backstop
  before network-enabled npm hydration; no repository command executes inside
  it other than the outer denied-network guard.
- Narrowed the accepted semver language to the shapes used by the reviewed
  lock. Independent differential fuzzing compared 18,873 accepted ranges over
  30 versions (566,190 cases) with npm 11's semver implementation and found no
  mismatch or non-range npm package classification.

## Ubuntu 24.04 hosted-runner compatibility revision

- GitHub-hosted Static, Unit, Contracts, and Secrets were observed failing
  before repository checks at the fixed unprivileged UID-map operation:
  `unshare: write failed /proc/self/uid_map: Operation not permitted`.
- Ubuntu 24.04 documents AppArmor restriction of unprivileged user namespaces.
  The approved repair does not disable that host-wide protection and does not
  install an AppArmor policy.
- The owner approved the exact 13,387-byte
  ST0106_HOSTED_NETWORK_ISOLATION_COMPATIBILITY_V1 handoff at SHA-256
  f53bee06a4ffc16ecbdb16e57ec828712badb6d9da8cfa014f7aa92105671fa2.
- The wrapper preserves its normal non-root user-namespace path. Only a failed
  fixed probe selects the root-owned, noninteractive
  sudo -> env -> unshare -> setpriv chain.
- Before any repository assertion or requested command executes, setpriv
  restores the original non-root UID/GID, clears supplementary groups, drops
  bounding/inheritable/ambient capabilities, and sets no_new_privs.
- Both the passwordless-sudo preflight and the namespace launch first use the
  kernel close_range interface through the fixed system Python. The hostile
  regression duplicates a connected socket above a lowered soft
  `RLIMIT_NOFILE` and proves that the child receives `EBADF` rather than an
  inherited network bypass.
- The assertion records a closed launch mode and, for the compatibility path,
  requires a fresh mount namespace plus empty groups and zero inheritable,
  permitted, effective, bounding, and ambient capabilities. Existing
  network/PID/route/interface/seccomp checks are unchanged.
- The local normal path is executable. Local passwordless sudo is unavailable,
  so the fallback runtime remains
  NOT_EXECUTED_PASSWORDLESS_SUDO_UNAVAILABLE; a GitHub-hosted pull-request run
  is required before this repair is hosted evidence.
