## Implemented execution boundary

- GitHub setup/checkout and source-constrained locked dependency hydration are
  the explicit network-enabled phase. Setup action caches are disabled.
- Before hydration, `scripts/validate_ci_hydration.py` runs inside the denied
  network/PID boundary and validates exact pins, approved origins, hashes, lock
  formats, workspace manifests, and npm configuration. Its npm checks use a
  positive ASCII semver grammar, require exact root/workspace and nearest
  transitive closure, verify captured versions against effective ranges, and
  allow an absent peer only with exact optional metadata. The reviewed ST-0103
  overrides are closed and substituted explicitly. No descendant of that
  preflight survives its PID namespace.
- After exact Node setup, bundled npm runs `ci --dry-run --offline` under the
  denied-network guard against a disposable metadata-only copy, fresh empty
  cache, and clean config. This checks npm's own peer/override/range semantics
  before real hydration. It must preserve the copied lock hash and leave no
  `node_modules` path.
- The hydration step directly invokes the pinned `uv`, Node, and npm tools with
  fixed registries and clean environments. It ignores uv source/config
  overrides, refuses Python builds, disables npm lifecycle scripts, and invokes
  no repository Make target or wrapper while network is enabled.
- `scripts/ci_job.sh` never hydrates. GitHub Actions starts it inside
  `scripts/run_network_denied.sh`; a local direct invocation enters that guard
  itself after the operator runs `make ci-hydrate`.
- The network guard rejects a root caller and sockets on standard descriptors,
  closes every other inherited descriptor, maps the current non-root identity,
  and uses fresh Linux user, network, and PID namespaces. It starts
  `scripts/assert_network_denied.py` before the requested command; the
  assertion fails closed unless both namespaces are distinct from the parents,
  the entry process is PID 1, the identity remains non-root, only loopback is
  present, and IPv4/IPv6 external routes are unavailable. An inherited
  `no_new_privs` seccomp filter denies network socket creation and connection,
  host pathname Unix sockets, and io_uring bypasses; local `socketpair` remains
  available for tool signalling. Each Make target repeats the assertion.
- The full worktree-and-history secret scan runs through the same guard. Its
  exact local equivalent is:

  ```bash
  scripts/run_network_denied.sh --home "$HOME" -- \
    /usr/bin/python3 -I scripts/scan_secrets.py --worktree --git-history
  ```

  A direct `python3 -I scripts/scan_secrets.py --worktree` run remains a
  diagnostic for source exports and is not equivalent evidence.

  network-enabled hydration step and replaced it with fixed direct `uv`/npm
  commands plus a denied-network metadata preflight.
