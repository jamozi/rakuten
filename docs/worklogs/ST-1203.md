## Implemented local recorded-only checks

- The generator now requires the complete existing `story`, `generation`, and
  `provenance` structures. Exact mapping fields and values, list order,
  canonical-input paths, predecessor Story/path pairs, installed repository,
  schema role/path pairs, provider reference, commands, format, fixture
  inventory, and pinned SHA-256 values must all remain exact. Unknown,
  missing, duplicated, reordered, or substituted material fails closed.
- Pinned-source validation applies the same exact provenance boundary before
  it opens any pinned file, then retains descriptor-relative reads and
  byte-hash verification.
- For dimensions selected by the current fixture contract, provider `date`
  keys must be `YYYY-MM-DD` calendar dates inside the inclusive request range,
  `country` keys must be lowercase ISO-style alpha-3 strings, and `device`
  keys must be exactly `DESKTOP`, `MOBILE`, or `TABLET`. Existing synthetic
  query and page checks remain in force. This does not invent alpha-3 to
  alpha-2 conversion or an external country registry.
- The bounded recorded profile supports only `date`, `query`, `page`,
  `country`, and `device`. Although the broader installed request schema also
  names `hour` and `searchAppearance`, source recordings that request either
  dimension fail closed before request hashing, and their provider keys also
  fail closed at the dimension-key boundary. No `hour` or search-appearance
  value semantics were added.
- Returned provider rows cannot exceed the request `row_limit`. The current
  page-dimensional recorded request accepts only the already selected
  `byPage` response aggregation. A general aggregation compatibility matrix
  for other dimension/request shapes remains outside this slice because it
  would require a broader contract decision.
- The CLI imports `sys` directly and uses exactly `sys.stderr` as the failure
  message sink. `os.sys` is absent and is no longer part of the allowed `os`
  attribute surface. The AST guard pins the complete outermost rooted
  attribute-chain inventory for each of the ten directly imported modules and
  requires exact observed coverage. It allows only the direct
  `print(..., file=sys.stderr)` use of `sys`; rejects private/dunder and
  `modules` traversal; and rejects dynamic/reflection names including
  `globals`, `locals`, `vars`, `getattr`, and `setattr`. Consequently,
  `sys.modules`, `os.sys`, `argparse._sys`, `tempfile._os.sys`, and nested
  `_socket`/`subprocess.Popen` recovery all fail closed.
- Negative coverage recursively exercises 226 exact-structure mutations:
  Story 39, generation 26, and provenance 161. It also covers malformed and
  out-of-range dates, malformed countries and devices, row-limit overflow,
  the selected page/aggregation relationship, four unsupported-dimension/key
  variants, and 29 AST capability-regression cases. All tests are
  deterministic, offline, credential-free, and network-free.

The AST control is a trusted-code regression guard over this exact generator,
not a Python sandbox. It does not establish safe execution of arbitrary Python
or replace source review, hash binding, denied-network runtime checks, and the
recorded-only boundary.

The manifest was rebuilt from `build_outputs` and published only at
`changes/st-1203/manifest.json` through the existing generator writer. The
three fixtures were not rewritten and retained their exact bytes.
