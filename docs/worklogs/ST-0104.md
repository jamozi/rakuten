## 2026-08-06 loader read hardening follow-up

This follow-up is a narrow mechanical hardening of the existing hand-maintained
ST-0104 loader. The approved Story, its dependencies, the cumulative contract
bundle, TST-002, security controls, prior ExecPlan, and current implementation
were re-read before editing. ST-0104 remains `APPROVED_FOR_IMPLEMENTATION` with
`open_decisions: []`; no new design, architecture, policy, contract, migration,
or public-API decision was required.

`ContractRepository._read_regular` now captures each read from the filesystem
root through every absolute repository-root component and artifact ancestor
using descriptor-relative traversal. It requires nonzero `O_DIRECTORY`,
`O_NOFOLLOW`, `O_NONBLOCK`, and `O_CLOEXEC`; compares path-before,
opened-before, opened-after, and path-after identities across device, inode,
mode, link count, size, nanosecond mtime, and nanosecond ctime; and rejects
symlinks, directory substitution, non-regular or multiply linked leaves,
replacement, in-place mutation, truncation, and extension. Reads consume the
captured size plus one extension-probe byte and preserve the caller's exact
2 MiB manifest or 16 MiB artifact ceiling. Filesystem failures are sanitized,
and every captured descriptor is closed once in reverse order; cleanup-only
failure is an error, while cleanup failure adds only a sanitized note to an
existing primary error.

## 2026-08-06 post-open rename timing assertion follow-up

This local-only, test-only follow-up addresses a filesystem-timing assertion,
not a loader defect. An independent repeated selection passed five cases and
failed one because the artifact-ancestor `after` case safely returned
`artifact ancestor changed before secure capture: nested/payload.bin` where the
test required the final `during read` classification.

A rename performed after the kernel returns an open descriptor can update the
renamed inode's ctime before the caller's immediate `fstat`. The repository-
root, artifact-ancestor, and leaf `after` assertions therefore accept exactly
their immediate post-open or final post-read rejection messages. Their
`before` variants and every unrelated assertion remain exact, and production
loader behavior is unchanged.

Neither `tests/st0104/test_loader.py` nor this worklog is an ST-0701
`STORY_SOURCE_PATHS` input. The included ST-0104 loader source is unchanged, so
no ST-0104 contract generation or ST-0701 regeneration is required. Formal
TST-002/CI, hosted clean-clone execution, human approval, status application,
release, staging, and production remain `NOT_EXECUTED`.

## 2026-08-06 descriptor-relative inventory hardening follow-up

This local-only follow-up closes the residual inventory traversal gap recorded
above. The approved ST-0104 Story, its dependencies, cumulative source
boundary, TST-002 contract, security controls, prior ExecPlan, and live loader
and tests were re-read before editing. ST-0104 remains
`APPROVED_FOR_IMPLEMENTATION` with `open_decisions: []`; no new design,
architecture, policy, contract, migration, or public-API decision was needed.

`ContractRepository._filesystem_inventory` now captures the repository from
the filesystem root through every absolute root component and nested directory
using only basename-plus-`dir_fd` operations after the filesystem root. It
requires nonzero `O_DIRECTORY`, `O_NOFOLLOW`, `O_NONBLOCK`, and `O_CLOEXEC`,
never follows symlinks, and no longer uses `os.scandir`, `entry.path`, or
pathname recursion. Directory and file identities use the complete device,
inode, mode, link-count, size, nanosecond mtime, and nanosecond ctime signature
at the applicable path-before, opened-before, opened-after, and path-after
checkpoints. Every scanned directory also has its exact sorted basename list
captured and descriptor-relatively compared after traversal, so persistent
add/remove/rename mutations do not depend on filesystem timestamp granularity.

Regular-file descriptors are closed exactly once immediately after their two
opened signature checks, while their parent descriptor, basename, and original
signature remain available for the final path-after comparison. This keeps the
canonical tree within a bounded descriptor budget. Root and directory
descriptors remain captured through final identity/listing checks and are then
closed once in reverse acquisition order. A cleanup-only failure fails closed;
cleanup failure adds only a sanitized note to an existing primary failure and
never masks it. Filesystem errors expose no underlying OS error detail.

Focused adversarial coverage verifies descriptor-only traversal and flags;
repository-root, nested-directory, and file swaps before and after open;
add/remove/replace/symlink/special-file and same-inode mutations; list/stat/open
failures; exact directory re-listing; immediate and terminal cleanup behavior;
and public construction of the canonical repository in a subprocess with soft
`RLIMIT_NOFILE=256`.
