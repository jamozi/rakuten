### Outcome and non-goals

The story imports all design artifacts into immutable `docs/upstream` and
`docs/canonical` trees, records a repository mapping manifest, and documents
the required reading order.

Database migrations, API/event revisions, application business logic,
toolchain/bootstrap work, provider access, cloud changes, publication, and
production status changes are out of scope.

### Ambiguities and safe decisions

- The source does not prescribe an exact source-to-destination mapping. Files
  under the package's `upstream/` path were mapped to `docs/upstream`; every
  other package file was mapped to `docs/canonical`. The original package path
  remains in `docs/manifest.json`.
- The package does not prescribe a repository manifest schema. A deterministic
  schema v1 records package path, repository path, byte count, and SHA-256 for
  all 105 source files.
- Read-only enforcement was unspecified. Imported files use mode `0444` in the
  working tree, while the durable control is exact hash/file-set verification.
  `.gitattributes` disables text conversion for canonical/upstream files,
  source ZIPs, and the pinned `docs/manifest.json` itself.
- The package-root `START_HERE.md` contains three broken relative links. It was
  preserved byte-for-byte; `docs/README.md` supplies the correct repository
  reading order.
- No formal Open Decision is attached to this story. The 15 global Open
  Decisions concern later implementation, external, or release work.
- The workspace does not expose a usable Git repository, so branch, PR, and CI
  evidence cannot be created here.
