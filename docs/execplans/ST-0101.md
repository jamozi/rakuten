## 3. Design

`workspace-layout.json` is a toolchain-neutral JSON source of truth so clean
bootstrap does not require PyYAML or a package manager. It enumerates the
approved managed roots, required tracked source files, and deterministic leaf
directory markers.

`scripts/bootstrap_workspace.py` uses only the standard library. Its default
mode materializes missing managed directories and generated markers; `--check`
performs no writes and rejects drift. Both modes fail closed on malformed or
unknown config fields, non-normalized/absolute/traversal paths, paths outside
the root allowlist, immutable design roots, symlink components, file
collisions, and missing/non-regular required files. Existing markers are never
overwritten: generated drift also fails closed. Missing markers are created
through verified directory descriptors. The writer fills and fsyncs an
anonymous Linux `O_TMPFILE`, temporarily makes the single-threaded process
non-dumpable so another same-UID process cannot acquire that descriptor through
procfs, atomically links it into place without replacement, checks descriptor/
path inode identity and link count, fsyncs the directory, and restores the
prior dumpability state. Unsupported `O_TMPFILE`, `prctl`, or procfs publication
fails closed rather than falling back to a visible temporary pathname.

Descriptor-relative `O_NOFOLLOW` traversal, preflight/write-phase directory
identity comparison, create-if-absent publication, and final inode checks
reject the tested path, symlink, regular-file, FIFO, directory-replacement, and
hard-link races. The command does not treat an actor with the same UID and
arbitrary rename/write access to the repository as a security boundary; such
an actor can already mutate the workspace directly. It must not run alongside
an adversarial same-UID workspace mutator. In particular, a directory moved
after its descriptor is opened can retain a marker on the pinned inode before
the final logical-path check reports failure.

The root Makefile exposes only `bootstrap` and `check-workspace`. It deliberately
does not define a misleading aggregate `test` or install dependencies before
the toolchain and base-CI Stories.

## 7. Approved ChatGPT Pro operational revision (2026-08-03)

The repository owner approved
`changes/st-0101/design-handoff.pro-browser.v1.yaml` for a narrow development-
tool workflow. The revision changes only the root policy overlay, project-local
Playwright configuration, a pinned fail-closed MCP wrapper, a fixture-driven
known-UI state machine, Story-local tests, and operational documentation.

The implementation uses an owner-approved, dedicated, previously authenticated
Chrome profile and the exact `https://chatgpt.com` origin. It allows only
navigate, snapshot, click, type, wait, and close; it stops before submission on
authentication, CAPTCHA, rate limit, origin, selector, option-set, or account
ambiguity. Pro and maximum effort must both be visibly proven by one of the
closed known-UI profiles. Prompt text reaches MCP only through the
`RAOS_CHATGPT_PROMPT` secret name. Local artifacts are owner-private beneath
ignored `.secrets/`, hash chained, and labeled `UNAPPROVED_PROPOSAL`.

This revision adds no production adapter, provider dependency, canonical
decision, or release authority. Fixture verification is required locally. A
live smoke requires a new Codex session plus the preauthenticated approved
profile and remains separate from formal TST-001 and human reconciliation.

## 8. Approved Pro-unavailability catch-path correction (2026-08-03)

The approved `design-handoff.raos-ask-pro.v1.yaml` importance boundary also
governs live UI failures discovered before prompt typing or submission. The
orchestrator therefore classifies only the pre-submission origin, selector,
unknown-UI, and model-option ambiguity codes as Pro unavailability. It records
the ordinary or gated terminal outcome with a run ID,
`submission_attempted: false`, the corresponding continue/stop directive, and
a hash-bound `PRO_UNAVAILABLE` event before the ephemeral prompt file is
removed.

The boundary is deliberately typed and stage-scoped. Allowlist violations,
raw-prompt tool arguments, invalid or drifted contracts, and other internal
invariants remain hard `REFUSED` results. No browser origin, MCP tool allowlist,
authentication, approval, live-smoke, or canonical-authority rule changes in
this correction. Verification uses scripted raw snapshots only and must prove
both importance branches, no prompt typing or send click, prompt cleanup,
single-line sanitized CLI output, record-chain integrity, and invariant
refusal.
