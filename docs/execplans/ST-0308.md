## Outcome and authority

ST-0308 now has a complete local persistence runtime for the Canonical
`repositories` and `transaction boundary` deliverables. The implementation is
source-bound to ST-0304, ST-0105, the corrected ST-0308 handoff inputs, and
eight executable matrices. It remains a local implementation candidate:

The earlier non-executable persistence-boundary reference is retained as a
historical pre-runtime artifact. It is not the current runtime entry point.

Unknown constraint syntax or owner-tree drift fails generation closed.

## Domain, Port, and adapter surface

The local runtime defines strict immutable Domain IDs, values, enums,
aggregates, and events for OPS, IAM, Portfolio, Catalog, Evidence, Editorial,
AI, and Policy. Inward Ports are aggregate-specific; generic CRUD, raw Row,
Mapping/dict, ORM instance, Session, and connection escape hatches are absent.
Fifty-three repository classes implement the closed surface.

The outer synchronous UoW is the sole transaction owner. Joined module UoWs
cannot commit, roll back, or create savepoints. Audit, Outbox, business
mutation, and idempotency completion share the same transaction. Every direct
ORM or trusted textual DML path is counted; any post-DML exception poisons the
transaction and prevents later SQL. Known commit, known rollback, and unknown
commit outcomes immediately discard registry/session/provider references.
Housekeeping faults cannot leak raw exceptions or reclassify a driver-confirmed
outcome.

Lock-version CAS, non-version state CAS, append-only, immutable-version-series,
child ownership, event specialization, and idempotent replay rules are
matrix-owned. Exact replay restores the typed success or approved deterministic
business-failure disposition; mismatch, ambiguity, and expired replacement
fail closed. Provider endpoint configuration accepts only the closed local
non-secret operational grammar; credentials, arbitrary JSON/string storage,
and live activation are rejected.

## Local verification

The local implementation gate uses CPython 3.14.6 and an ephemeral exact
PostgreSQL 18.4 installation with network-denied/offline flags. The final
required checks are:

1. `python scripts/build_st0308_persistence.py` and `--check`;
2. `pytest -q -p no:cacheprovider tests/st0308_persistence` with the exact
   PostgreSQL 18.4 binary/library environment;
3. the retained `tests/st0308` and `tests/st0308_reference` suites;
4. Ruff format/check and strict mypy over the runtime owner, Domain, Ports,
   adapters, and Story tests;
5. Python compile/import, focused sensitive-material scanning, canonical import
   verification, workspace drift review, and `git diff --check`; and
6. a fresh independent integration audit of repository coverage, transaction
   fault paths, physical invariants, secret boundaries, and terminal cleanup.

The completion record is
`changes/st-0308/LOCAL-IMPLEMENTATION-COMPLETION-20260824-v2.yaml`. Append-only
status evidence is deliberately deferred to a later status-only branch because
