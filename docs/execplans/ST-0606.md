# ST-0606 — Evidence Workspace UI local implementation ExecPlan

## Objective

Implement the maximum-safe local ST-0606 consumer without choosing OD-010 or
weakening the ST-1101 disabled route/auth boundary. Preserve the historical V1
model and add a deterministic V2 recorded/synthetic read projection for the four
canonical EVD screens.

## Inputs and dependency order

1. Canonical ST-0606 record and UI/accessibility/security/test catalogs.
2. ST-0604 current lifecycle contract and generated source.
3. ST-0605 current runtime contract, recorded fixture, coverage evaluator,
   report, and attestation provenance.
4. ST-1101 disabled route guard and unresolved OD-010 boundary.

All repository bindings are exact SHA-256 anchors in the V2 contract. ST-0604
is authoritative for current lifecycle availability; the ST-0605 Packet in the
synthetic evaluator input is not reclassified as a live lifecycle record.

## Implementation slice

- Add a versioned V2 contract and sanitized recorded/synthetic presentation
  fixture.
- Add one strict owner generator that verifies dependency bytes and semantics,
  reruns the ST-0605 evaluator, verifies every attestation
  kind/subject/input/contract/decision binding, and emits deterministic JSON,
  TypeScript, and provenance manifest artifacts.
- Add typed immutable Source, Fact, Conflict, Coverage, Matrix, attestation, and
  screen/view contracts in `packages/web-ui`.
- Keep all routes unregistered and every auth/data/network/action/write/public
  authority false.
- Define semantic table/status/landmark/keyboard contracts and deterministic
  Source reachability within two focus steps; do not claim browser evidence.
- Add hostile tests for input objects, provenance tampering, unknown-to-zero
  coercion, route escalation, source reachability, commercial inputs, symlinks,
  duplicate JSON keys, and semantic accessibility drift.
- Preserve V1 exports and add only the minimal V2 exports to the shared index.

## Minimum checks

- Python compile and focused `tests/st0606_v2`.
- Owner generation and `--check`.
- Focused Node-native V2 tests with Node 24.18.1.
- Strict TypeScript, ESLint, and Prettier for owned files.
- Current ST-0604, ST-0605, and ST-1101 regression checks.
- Sensitive-data/secret scan and `git diff --check`.

## Hard stops

No credential, live provider, network, browser, backend, database, route
activation, publication, staging, release, Production write, destructive
operation, or auth-transport decision is permitted. Formal TST-022/TST-024 and
canonical status transitions remain outside this local slice.

## Completion boundary

`LOCAL_CODE_COMPLETE` and local integration evidence may be recorded only after
the owner generator is reproducible and all locally executable focused checks
pass. This plan cannot establish `VALIDATED`, formal browser/accessibility,
staging, release, publication, or Production status.
