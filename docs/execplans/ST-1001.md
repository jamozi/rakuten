# ST-1001 — local public app shell and policy pages

## Story and outcome

Implement the exact `PUB-004` through `PUB-007` public policy routes as a
local-only Next.js App Router shell. The outcome is readable server-rendered
HTML, deterministic metadata, header/footer/navigation/breadcrumbs, safe
policy copy, and explicit unresolved-decision states.

Non-goals are a live site identity or domain, final legal/privacy/operator
copy, analytics, cookies, affiliate CTA, article/category/home routes,
publication, staging, release, and Production.

- Register only four local policy routes and no homepage/article/category/CTA.
- Use server components and typed text records; no raw HTML or arbitrary URL.

## Proposed design

The versioned YAML contract is the owner source for policy text and boundary
values. A deterministic Python generator validates Canonical anchors and emits
one TypeScript content module, one recorded JSON projection, and one runtime
manifest. Pure TypeScript validates the generated closed records and produces
route metadata. React server components render the shell with semantic HTML.
Next.js config applies exact-route noindex and defensive response headers.

Failure is closed: unknown route IDs, contract drift, duplicate IDs/routes,
renderable markup/URLs, identity values, enabled tracking, or authority values
make generation or model validation fail. Generated publication is atomic and
foreign-file preserving. Rollback is the single Story commit.

Accessibility uses `lang=ja`, skip link, native landmarks, one H1, labelled
navigation, current-page indication, text status labels, visible focus,
responsive wrapping from 320 CSS px, and no animation. No WCAG conformance is
claimed before formal/manual checks.
