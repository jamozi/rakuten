# ST-1702 ExecPlan — category fixtures and rules

## 1. Story and outcome

Implement the maximum safe local ST-1702 boundary: a strict synthetic
category schema, four recorded golden-product fixtures, three identity-review
cases, and an effect-free DEV/CI load seam. OD-001, OD-006, and OD-007 remain
unresolved; no category is activated and no Canonical status is changed.

Read the integration design and protocol, selected Story and dependencies,
Open Decisions, freshness policy, identity review boundary, TST-020, and
SEC-DATA-003/004/006, SEC-AI-007, SEC-SDLC-002/006/009/012. The historical
V1 plan and all ST-1701, ST-0504, and ST-1401 bindings remain authoritative

## 3. Invariants

- Synthetic fixtures never become product facts or publication evidence.
- The suitcase category remains an unapplied candidate under OD-001.
- OD-006 always returns Human Review; automatic merge/split stay disabled.
- OD-007 remains provisional and disabled with no overrides.
- Missing approval or evidence is never converted to success or zero.
- Provider, network, persistence, publication, activation, release, and
  Production authority remain false.

## 4. Design

Add a closed JSON owner contract and deterministic generator. The generator
exact-binds Canonical and dependency artifacts, validates the domain model,
and atomically publishes JSON, an immutable Python wrapper, and a provenance
manifest. A recorded adapter reparses and rehashes the fixture on every load;
an inward port and one-call application service expose only immutable values.

## 5. Milestones

1. Rebind the historical plan to the integration head without semantic drift.
2. Add V2 contract, domain, port, service, adapter, and owner generator.
3. Generate the recorded fixture/wrapper/manifest.
4. Add positive, hostile-input, authority, generation, and compatibility tests.
5. Run focused and affected checks and freeze exact local evidence.

## 6. Test plan

The TST-020 local analogue covers required schema/product/case counts,
identity scenario differences, immutable/redacted values, exact hashes,
deterministic loading, one-call behavior, tamper rejection, and every disabled
authority. V1 and dependency suites run in separate pytest processes. Static
checks include Ruff, strict mypy, compile/import, generator `--check`, source
scans, Canonical import verification, and Git diff validation.

## 7. Evidence and non-goals

Generated artifacts, focused command output, the completion record, and the
worklog are local evidence only. Formal TST-020, Domain Reviewer approval,
live provider/database activity, staging, publication, release, and Production
remain truthfully `NOT_EXECUTED`.
