# ST-0701 ExecPlan - AI contract registry loader

## Outcome and authority

Implement the approved `ST-0701` Story objective
`Task/Prompt/Schema/RouteをHash検証` from the installed ST-0104 repository and
the finalized ST-0003 AI governance candidate. The canonical Story has
`open_decisions: []`, depends only on ST-0104 and ST-0003, and accepts the
implementation when unknown identifiers and hash mismatches fail closed.

The local outcome is one strict, deterministic JSON task projection, one
standard-library immutable adapter, exact source/generated provenance, and an
isolated failure-focused suite. Effective canonical status and formal TST-001
and TST-017 execution remain unchanged.

## Invariants

- The runtime JSON shape remains exactly the live adapter schema; there is no
  second runtime registry format.
- Every compiled task is sorted and unique by exact `task_code`; case-fold
  collisions also fail generation.
- Prompt frontmatter must agree with both Task and Prompt registry fields.
- Every task-output schema path, ID, and SHA-256 must agree across Task,
  Schema registry, JSON bytes, and installed repository metadata.
- Route metadata is candidate data only. Compilation never activates a route,
  performs provider selection, or validates current provider facts.
- Unknown local paths never fall back to a URL or network fetch.
- Generated files are changed only by the generator. `--check` performs no
  write, sync, cache fill, network access, database access, or external action.

## Verification boundary

Focused local tests and static checks can establish a reviewable
`IMPLEMENTATION_CANDIDATE`. They do not establish formal CI evidence, live
provider behavior, route certification, release approval, staging, or
production readiness. TST-017's recorded OpenAI adapter surface remains
downstream ST-0703 scope; ST-0701 exercises only its registry prerequisite.
