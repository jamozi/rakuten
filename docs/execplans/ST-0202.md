# ST-0202 ExecPlan - Local S3-compatible object service

## Story and outcome

- Story: `ST-0202`, `EPIC-02`, P0/S, MVP.
- Objective: provide local storage for Raw/Snapshot artifacts.
- Dependency: `ST-0102`.
- Deliverables: one S3-compatible service and bounded bucket bootstrap.
- Acceptance criterion: authenticated put/get/version fixture.
- Required suite: release-blocking `TST-014` in the canonical CI environment.
- Security controls: `SEC-DATA-003`, `SEC-DATA-004`, `SEC-DATA-008`,
  `SEC-INFRA-001`, `SEC-INFRA-006`, `SEC-SDLC-003`, and `SEC-SDLC-004`.
- Blocking policy input: `OD-014` remains `HUMAN_DECISION_REQUIRED`; its safe
  default disables automatic deletion and does not authorize a retention
  period or object lifecycle-delete policy.

The scoped outcome is a deterministic local/CI service candidate and an
authenticated artifact fixture boundary. It is not production infrastructure.
No image pull, service start, readiness probe, authenticated S3 operation,
container scan, or formal TST-014 result is claimed without real runtime
evidence.

## Invariants

- The exact image index, linux/amd64 manifest, and config digests are pinned.
- The service command disables master telemetry and all unneeded interfaces.
- Persistent operator commands require one decimal fixed port in
  `1024..65535`. The disposable `test` command alone adds an exact private
  runtime Compose override whose one `!override` port entry omits `published`
  to request an Engine-assigned port; no zero sentinel, range, or wrapper-
  preselected single port is used. The override retains the internal network
  and adds exactly one project-scoped non-internal bridge with
  `enable_ip_masquerade=false`, because Docker Engine does not program host
  mappings for an internal-only endpoint. The normalized Compose model must
  retain that exact loopback-only/TCP and network shape before container
  creation and every project Compose use. The observed mapping must be one
  decimal loopback port in `1024..65535`.
- `/status` and `/healthz` are readiness signals only; neither can satisfy the
  authenticated acceptance criterion.
- `init: true` retains the root `/sbin/docker-init` process at PID 1. Runtime
  verification must require `.HostConfig.Init=true` and two independent
  fail-closed probes. The root probe verifies exact init identity and exactly
  one direct service child after excluding only its own observer PID. It
  verifies that child's PPid, all four UID/GID values, zero effective
  capabilities, non-zombie state, and start time twice, but does not attempt a
  cross-UID executable read. The exact `1000:1000` probe independently resolves
  the child and verifies the complete server shape including `/usr/bin/weed`
  twice. Each emits only its distinct fixed token.
- `raos-raw` is private, object-lock-capable at creation, and versioned.
- Accepted artifacts round-trip `sha256`, `content-type`, `source`,
  `acquired-at`, and `retention-class`; a body/hash mismatch is rejected.
- `OD-014` is not resolved locally. Default retention and lifecycle deletion
  are forbidden, and automatic deletion remains disabled.
- Effective canonical Story and suite status remain unchanged until governed
  status evidence is reviewed.

verify orchestration only; they do not replace the hosted runtime smoke.

## 2026-08-20 split-UID process verification decision

- `approved_story`: `ST-0202`.
- `approved_scope`: the Base CI restoration slice may replace only the
  post-readiness process assertion, its exact contract, owned tests,
  documentation, and mechanically derived provenance.
- `source_design_refs`: the pinned SeaweedFS revision
  `1355c7a102194d6c461baf090eff50367b575afb`, its Docker build and entrypoint,
  Linux `proc_pid_exe(5)` access semantics, `ptrace(2)` access checks, and
  hosted Storage attempts `32372018897` / `96434544048` and `32372405468` /
  `96435870237`.
- `decision`: retain a root no-added-capability probe for init and complete
  server topology/status/start-time checks, then run one exact
  `docker exec --user 1000:1000` probe that independently performs complete
  server status/start-time/executable checks. Both probes make two stable
  observations and return only distinct fixed tokens.
- `rationale`: Linux applies ptrace access checks to `/proc/<pid>/exe`; the
  container root observer intentionally lacks `CAP_SYS_PTRACE`, while the
  official entrypoint runs `/usr/bin/weed` as UID/GID 1000. A same-UID read
  preserves exact executable verification without increasing privilege.
- `rejected_alternatives`: adding `CAP_SYS_PTRACE`, privileged mode, host
  procfs, Docker top or command-line inspection, comm-only identity, removing
  executable verification, logging dynamic proc values, or passing PID/start
  time between probes.
- `constraints`: no process environment or command-line inspection; no dynamic
  PID/start-time argument, environment, file, or output; no change to image,
  Compose, secret transport, networking, bucket semantics, or retention.
- `security_and_approval_gates`: no credentials, provider write, publication,
  release, staging, Production, status promotion, new capability, or OD-014
  resolution.
- `acceptance_criteria`: exact root and `1000:1000` exec shapes; every required
  init/server field; two observations per probe; exact one-token output; all
  malformed, missing, changed, padded, extra, unknown, or nonzero cases fail
  before version and authenticated fixture execution.
- `required_test_evidence`: `bash -n`, isolated ST-0202 pytest including
  adversarial fake-Docker coverage, deterministic generator install/check,
  Ruff, strict changed-Python type checks where applicable, Canonical import
  verification, workspace drift check, and a new Hosted Storage run.
- `open_decisions`: `OD-014` remains unchanged and outside this process
  assertion decision.

## Completion boundary

Local generation and focused tests can establish an implementation candidate;
they cannot change the effective canonical `NOT_STARTED / NOT_EXECUTED` status.
Formal TST-014 remains `NOT_EXECUTED` until canonical CI runs the complete
hash/version/tamper/retention-hook suite with reviewed evidence. The container
vulnerability scan and the SeaweedFS 4.29 object-lock/version-delete regression
also remain mandatory runtime gates.
