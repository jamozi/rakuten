# ST-0105 ExecPlan — Generate Python and TypeScript contract types

## 1. Story and outcome

- Story: `ST-0105`, `EPIC-01`, P0/M, MVP.
- Objective: deterministically generate Python types and TypeScript types/clients
  from the installed contract repository.
- Dependencies: `ST-0104`, `ST-0102`, and `ST-0103`.
- Required suite: `TST-004` (formal environment: CI).
- Acceptance criterion: two complete generations have no byte difference.
- Outcome: hash-bound Pydantic v2 models, TypeScript schema bindings, separate
  Public/Admin/Internal fetch clients, an AsyncAPI metadata registry, trusted
  generation commands, and rollback-safe installation.

HTTP handlers, broker behavior, runtime Content AST policy validation, domain
mapping, fixtures owned by downstream runtime Stories, base CI, publishing,
deployment, and external state are explicit non-goals.

## 2. Context read

The canonical integration protocol, backlog row, critical path, TST-004 suite,
ST-0003/ST-0004 generation contracts, ST-0102/ST-0103 toolchains, installed
ST-0104 repository/loader/manifest, and repository instructions were reviewed.
ST-0105 has no attached requirement ID, design reference, or Open Decision.

The verified ST-0104 manifest owns 306 artifacts: 224 standalone Draft 2020-12
JSON Schemas, three OpenAPI 3.1.1 documents with 185 operations, one AsyncAPI
3.0.0 document with 105 messages, and supporting contracts. The installed
repository, not the source archive or network, is the only generation input.

The exact toolchain is CPython 3.14.6, Pydantic 2.13.4,
datamodel-code-generator 0.71.0, Node 24.18.1, TypeScript 6.0.3, and
`@hey-api/openapi-ts` 0.99.0. Tool versions and all output bytes are recorded in
`changes/st-0105/manifest.json`.

## 3. Invariants

- Canonical/upstream/ZIP inputs and the installed ST-0104 repository remain
  immutable during generation.
- Every input is read through the ST-0104 manifest-owned loader and rechecked by
  byte count and SHA-256; network retrieval is forbidden.
- Full relative paths plus a stable index derive collision-free Python and
  TypeScript schema names.
- Public, Admin, and Internal OpenAPI operations never share a client export.
- Generated output roots contain exactly the manifest-listed regular files: no
  symlinks, bytecode, unknown files, temporary paths, or timestamp headers.
- A durable journal exists before either output namespace changes. A failed or
  interrupted pre-commit install restores both prior output trees and manifest;
  a durable committed install retains the new state and resumes cleanup.
- Every managed ancestor is opened from the physical repository root with
  `O_NOFOLLOW`; all stage, rename, manifest, fsync, rollback, and cleanup
  operations remain relative to pinned directory descriptors.
- A rollback error never deletes a journal or stage that may contain the only
  prior tree. The next mutating install retries recovery; read-only commands do
  not recover or write.
- Local TST-004-equivalent results never become formal CI evidence or change
  effective canonical status.

## 4. Design

`scripts/build_st0105_generated_contracts.py` validates exact tools and the
pinned ST-0104 manifest SHA, copies the entire verified corpus into a private
temporary directory, and builds two deterministic synthetic entry documents.
The JSON Schema entrypoint drives modular Pydantic v2 generation; the OpenAPI
entrypoint makes all 224 standalone schemas addressable to TypeScript codegen.

Each original OpenAPI document independently generates a bundled fetch client
under `clients/public`, `clients/admin`, or `clients/internal`. Bundling avoids
an incompatible/deprecated external client dependency and leaves the generated
package self-contained. The package inherits the strict root TypeScript config.
The sole override, `exactOptionalPropertyTypes=false`, is isolated to generated
code because the pinned generator writes optional property assignments that do
not compile with that flag; strict mode, unchecked-index checking, no emit, and
the remaining root controls stay active.

The AsyncAPI document generates a frozen channel/operation/message registry,
not a broker runtime. Provenance headers bind all Python and TypeScript sources
to the relative ST-0104 manifest path and SHA.

Builds occur entirely in a private temporary root. `--check` compares the new
manifest and both complete trees without writing. Installation serializes on a
directory lock and publishes a descriptor-owned, fsynced write-ahead journal
before staging. `STAGING` and `PREPARED` recover toward the old state;
`COMMITTED` recovers toward the new state; `ROLLED_BACK` resumes cleanup. Each
existing tree uses Linux `renameat2(RENAME_EXCHANGE)` and each fresh tree uses a
durable parent-relative rename. Manifest replacement, terminal state, stage
cleanup, terminal-journal-to-cleanup-tombstone rename, and tombstone removal are
separately fsynced. Recovery attempts both trees and the manifest independently,
retains all recovery material if any step remains uncertain, and blindly
removes a partial terminal cleanup tombstone without parsing it.

`scripts/codegen_toolchain.sh` validates exact uv, Node, and bundled npm before
an allowlisted Make invocation. Mutable `hydrate` synchronizes the locked
Python/Node environments and caches as a separate operation. `install` then
uses a pending-tolerant real-storage prerequisite, recovers any transaction,
and only then verifies exact repository tools before mutating generated
artifacts. Every tool-path ancestor is opened with `O_NOFOLLOW`. `check`,
`test`, `typecheck`, and composite `gate` validate an already-hydrated
environment with offline, no-cache, and no-sync controls; pytest cache and
bytecode writes are disabled. Public-wrapper recovery is exercised only in a
disposable temporary repository.

## 6. Test and evidence plan

- Re-run the generator twice in no-write mode, require byte-identical reports,
  and prove every output hash and mtime remains unchanged.
- Reconcile 306 source artifacts, 224 unique schema bindings, 185 unique HTTP
  operations split 6/171/8, 22 AsyncAPI channels, 37 AsyncAPI operations, and
  105 messages.
- Compile every generated Python source without bytecode, import all 224 model
  exports, and build each Pydantic JSON Schema.
- Compile the generated TypeScript package with exact Node/TypeScript and verify
  each surface exports exactly its source operation IDs.
- Reject unsafe paths, symlinks, malformed/unsorted manifests, extra files,
  source/tool drift, and injected generation failures.
- Inject stage, namespace, manifest, rollback, and cleanup failures. Kill a
  subprocess after each Python/TypeScript/manifest namespace mutation, after
  durable commit, and during cleanup; prove the next install-side recovery is
  idempotent and selects the documented old/new state.
- Replace each managed ancestor with a symlink in private fixtures and prove no
  stage, output, manifest, or sentinel outside the repository changes.
- Snapshot `.venv`, `node_modules`, package caches, pytest cache, generated
  outputs, and manifest around wrapper `check`; trace subprocess network calls
  and reject every IPv4/IPv6 socket.
- Run the composite predecessor contract gate, ST-0105 suite, affected ST-0103
  workspace regression, toolchain gates, prior Story suites in isolation,
  workspace/import/build checks, and protected-source hashes.
- Freeze append-only evidence only after source, docs, tests, outputs, locks,
  and manifest are final; retain effective `NOT_STARTED / NOT_EXECUTED`.

## 7. Risks and decisions

- External generators are deterministic inputs, not maintained source. Do not
  post-format their outputs or require them to satisfy hand-authored
  mypy/Pyright conventions; exact regeneration, Ruff syntax lint, Python
  compile/import/Pydantic checks, and TypeScript compilation are the boundary.
- Schema generation can produce transitive helper types in addition to the 224
  stable top-level bindings. The manifest binds the complete output tree while
  `schema_bindings` identifies the one stable export per standalone input.
- The combined wrapper is Linux-specific because rollback-safe replacement uses
  `renameat2`. Native Windows and hosted clean-clone behavior remain unexecuted.
- Formal TST-004 requires CI, which is owned by ST-0106. This Story can produce
  only a local implementation proposal.
