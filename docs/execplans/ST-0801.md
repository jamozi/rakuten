# ST-0801 ExecPlan - Content AST types and validator

## Story authority and outcome

- Story: `ST-0801`, `EPIC-08`, P0/L, MVP.
- Approved implementation slice: `CONT-SLICE-002`, Content AST v1 domain types
  and loader.
- Dependencies: `ST-0004` and `ST-0105`.
- Requirements: `FR-007` and `FR-008`.
- Deliverables: types, loader, and fixtures.
- Acceptance: raw HTML, finance fields, and review body fields are rejected.
- Required suite: release-blocking `TST-020` in CI.
- Open decisions: none attached to the Story or implementation slice.

The local outcome is a strict structural boundary around the installed,
checksum-pinned Content AST v1 schema and ST-0105 generated Python and
TypeScript bindings. Local completion does not change the canonical
`NOT_STARTED / NOT_EXECUTED` status.

## Preflight and immutable inputs

1. Follow the canonical precedence in the integration design and Codex
   handbook; read the ST-0801 backlog entry, TST-020 catalog entry,
   `SEC-APP-001`, `SEC-APP-004`, the open-decision register, ST-0004 content
   package, and ST-0105 generated-binding manifest before editing.
2. Preserve `zip/**`, `docs/canonical/**`, `docs/upstream/**`,
   `docs/manifest.json`, `contracts/raos-v0.4/**`, and generated ST-0105 files
   byte-for-byte.
3. Treat the installed Draft 2020-12 Content AST schema as structural
   authority. Verify its exact SHA-256 and byte count before a bounded read,
   then validate before projecting through generated Pydantic types.
4. Reuse the generated Python and TypeScript bindings. Do not hand-edit them
   or add a second type-generation path.
5. Treat pre-execution integrity for generated Python as the ST-0105
   deployment/codegen gate's responsibility. The runtime loader checks only
   selected generated files on disk at the call boundary after normal import;
   the ST-0801 manifest generator verifies every pinned ST-0105 output.
6. Reject duplicate JSON members, non-finite numbers, unsupported schema
   versions, unknown fields, structural violations, generated-binding drift,
   and duplicate block IDs without logging or echoing rejected content.
7. Keep script/iframe-like text as text. Escaping belongs to a later renderer;
   raw HTML/script/iframe/event-handler fields remain prohibited.
8. Do not infer article-template, Claim/Evidence, Recommendation, review,
   Disclosure, API, database, publication, or provider behavior.

## Approved implementation scope

1. Export the installed generated `ContentAst`, `ArticleType`, and
   `PublicationFlags` types through the editorial domain package.
2. Add a hash- and size-bound loader using descriptor-relative, nonblocking,
   no-follow reads. Read exactly the reviewed byte count and one EOF probe.
3. Validate JSON with the frozen schema before generated-model projection and
   enforce the AST-local unique `block_id` rule.
4. Initialize the six affected generated wrapper models and Content AST model
   under one module lock exactly once. Both load and dump enter the same
   readiness boundary.
5. Serialize deterministically, parse and schema-check the serialized
   snapshot, reproject that snapshot, and run AST-local policy only against
   the snapshot rather than the caller's mutable original.
6. Promote the existing exact `jsonschema==4.26.0` pin from dev-only to the
   runtime dependency set. Keep generated modules type-visible to mypy while
   silencing diagnostics within generated code only.
7. Cover the five valid fixtures, ten schema-invalid fixtures, one AST-local
   duplicate-ID fixture, four later-policy fixtures, and all 24 block types.

## Deferred and forbidden scope

- Renderer output encoding and XSS execution are deferred; the loader only
  proves that schema-valid text survives unchanged.
- Article required-block/order/product-count rules are `CONT-SLICE-003`.
- Claim resolution and evidence coverage are later Claim/Evidence scope.
- Recommendation calculation, review policy, Disclosure placement, API/DB
  persistence, publication, and all provider integrations are not
  implemented.
- No canonical status overlay, ST-0005 evidence, formal suite result,
  publication action, credential access, network retrieval, or production
  behavior is created.

## Test and matrix plan

- Round-trip all five frozen valid article fixtures deterministically.
- Reject all ten schema-invalid fixtures and the AST-local duplicate block ID;
  explicitly retain the other four policy fixtures for later slices.
- Run minimum payload, unknown field, required field, type, duplicate ID,
  finance, raw URL, upper-bound, and round-trip cases for every block type.
- Map genuine text/rich-text fields for the 18 block types that expose one and
  prove exact text preservation. Classify six blocks without such a field and
  all renderer escaping, public projection, and Claim-resolution rows as
  deferred rather than executed.
- Verify the exact 24 by 12, `CT-0101` through `CT-0388` matrix inventory and
  its explicit executed/deferred ownership.
- Exercise concurrent first use, FIFO/nonregular/size drift, descriptor-close
  hygiene, parser resource errors, mutation-safe serialization, schema/model
  coercion gaps, and redacted error surfaces.

The frozen schema accepts RFC3339 leap-second syntax. The current ST-0105
generated Pydantic `AwareDatetime` projection cannot represent that value, so
the loader fails closed with a redacted `MODEL` error. It neither reclassifies
the value as a schema violation nor invents a normalization. Resolving that
generated-binding limitation requires a future generated-contract revision.

correctness, human review, release approval, or production readiness.
