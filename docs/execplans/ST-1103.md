# ST-1103 ExecPlan — Freshness and operations UI

## 1. Story and outcome

Implement the maximum safe local `ST-1103` boundary: deterministic headless
models for `FRESH-001..003` and `OPS-001..005`, exact recorded projections from
declared dependencies, status semantics that do not rely on color, and safe
effect-free review intents. Non-goals are route registration, React/DOM work,
authentication, authorization, persistence, live providers, mutation, retry,
cancel, redrive, Kill Switch execution, publication, staging, release, and
Production.

## 2. Context read

Read RAOS Master README, integration design, Canonical/Open Decisions, Codex
rules, selected Story, UI design, screen/component catalogs, Operations design,
SEC-OPS controls, TST-022/TST-024, and the complete installed ST-1101, ST-1401,
ST-1404, and ST-1103 local boundaries. `OD-007` remains blocking with the
installed conservative policy disabled; ST-1101 remains a disabled headless
foundation. Incident, Kill Switch, Audit, link-health, and refresh-proposal
stores are not declared ST-1103 inputs and remain unavailable.

## 3. Invariants

- AI or local code never approves, mutates, publishes, activates, or releases.
- ST-1401 unknown/stale state is not coerced to zero, fresh, or success.
- ST-1404 recorded state is not represented as durable runtime evidence.
- No raw payload, source body, review body, credential, secret, or callback is
  stored in generated or UI artifacts.
- Status is always text + code + icon and never color-only.
- Finance and affiliate economics are not inputs to this workspace.
- Public/internal isolation and Canonical status separation remain intact.

## 4. Proposed design

Add an additive V2 TypeScript model while preserving V1 bytes. A Python owner
generator executes exact ST-1401 domain evaluation/selection and constructs
validated ST-1404 recorded job values, then atomically publishes a bounded JSON
projection, immutable TypeScript wrapper, and manifest. V2 parses and validates
that compiled fixture, creates a deeply frozen screen model, and optionally
creates only a closed human-review request intent bound to an exact target
fingerprint. Unavailable owner Stories render explicit unavailable tables.
Rollback is deletion/revert of the additive V2 commit; V1 remains functional.

## 7. Evidence plan

Local evidence consists of focused command output, generated manifest, exact
fixture hashes, completion record, and this worklog. Formal browser/a11y,
staging, live, release, publication, and Production evidence remain
`NOT_EXECUTED` and are not promoted.

## 8. Risks and decisions

The Canonical catalogs do not prescribe a screen-to-component mapping. The V2
uses the smallest reversible mapping derived from exact component purposes and
records it as local headless semantics. No route or DOM ownership is inferred.
Missing owner Stories remain explicit unavailable boundaries. Review intents
are not commands and cannot be dispatched or persisted.
