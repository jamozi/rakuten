# ST-0705 — deterministic AI-output validation runtime ExecPlan

## Objective and authority

- Canonical Story: `ST-0705`, AI output validation.
- Dependencies: ST-0702 typed prompt context, ST-0703 provider response
  envelope, and ST-0605 Claim/evidence coverage.
- Local scope: pure deterministic evaluator, immutable content-addressed
  profiles, recorded adapter/application boundary, owner generator, fixtures,
  tests, documentation, and local completion evidence.
- Hard stops: no live provider or credential access, repair call, filesystem or
  database persistence in the evaluator, Content AST conversion, publication,
  approval, staging, release, or Production action.

## Implementation slices

1. Generate exact AIT-001 through AIT-012 profiles from pinned canonical task,
   schema, alignment, and owner-contract inputs; bind every task/prompt runtime
   check to an evaluator gate or predecessor receipt.
2. Parse strict canonical JSON object bytes with duplicate-key, non-finite,
   size, local-reference, schema, format, canonical UUID, and version checks.
3. Validate explicit resource, scalar, order, policy, secret, taint, review,
   Claim-count, and semantic locators without heuristic field discovery.
4. Require closed hash-bound context and semantic receipts, and distinguish the
   ST-0703 exchange digest, raw-output digest, and canonical-output digest.
5. Consume ST-0605 only through an exact Article/body/Packet/Claim/evaluation/
   report binding.  Preserve frozen-schema gaps as `UNEVALUABLE` and leave AI
   output-to-Content AST conversion to ST-0806.
6. Expose deterministic failure disposition while limiting one-repair
   eligibility to AI-OUT-001/002; the runtime performs no repair or fallback.
7. Add a strict generated-registry loader, recorded ENV-DEV/CI adapter, local
   application service, transactional owner generation, critical negative-path
   tests, and local-only evidence records.

## Completion boundary

Local completion requires owner generation/check, focused historical and
runtime tests, Ruff, strict mypy, compile/fresh import, focused sensitive-data
scan, and `git diff --check`.  It cannot satisfy formal TST-019/TST-020 or
advance Canonical, live, staging, release, publication, or Production status.
