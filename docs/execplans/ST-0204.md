# ST-0204 ExecPlan - Configuration and secret loader

## Story and outcome

- Story: `ST-0204`, `EPIC-02`, P0/M, MVP, one-PR preferred.
- Objective: provide environment-specific typed configuration and logical
  Secret references.
- Dependencies: `ST-0102` and `ST-0103`; no open decision is attached.
- Deliverables: a language-neutral config schema and redacted diagnostics.
- Acceptance: required settings fail closed and Secret material is never
  logged.
- Required suites: release-blocking `TST-005` in CI and `TST-031` in CI plus
  staging.

The scoped outcome is a strict provider-neutral configuration boundary. It
does not retrieve a Secret, configure a provider, or inject configuration into
browser code.

## Preflight

1. Read the master/integration decisions, open-decision register, exact
   ST-0204 Story, TST-005/TST-031, environment matrix, security/privacy design,
   data classification, security controls, and Codex handbook.
2. Preserve `zip/**`, `docs/canonical/**`, `docs/upstream/**`, and
   `docs/manifest.json` byte-for-byte.
3. Keep runtime settings separate from Secret values. Accept only a bounded
   map of logical `secret://` references and expose no raw-value accessor.
4. Load only an explicit mapping or an explicitly requested process
   environment. Do not read `.env`, files, network, provider SDKs, or process
   state at import time.
5. Fail closed on missing, unknown, malformed, duplicated, oversized, or
   coercible inputs without echoing untrusted input in errors.
6. Prove reference canaries are absent from diagnostics, representations,
   serialization, Pydantic structured errors, exception pickles,
   stdout/stderr, and log records. Reject hostile string subclasses without
   invoking caller-controlled overrides. Do not promote local results to
   formal TST-005/TST-031 status.
7. Bound supported `model_validate_json()` input to 32 KiB. Treat direct
   low-level `TypeAdapter.validate_json()` parsing and explicit calls to
   `BaseModel` validation-bypass methods as unsupported APIs; document that a
   malformed-JSON parser error is created before the model schema runs.
8. Forbid subclassing the runtime model and opaque reference. Revalidate and
   normalize existing model inputs, and accept only exact base reference
   instances so inherited display or pickle overrides cannot escape redaction.
9. Keep Pydantic-core validation patterns separate from emitted JSON Schema
   patterns. Require absolute-end matching under both ECMA-262 and Python Draft
   2020-12 validation, and pre-scan supported JSON input for duplicate members
   at every object depth before model validation. Snapshot mutable bytearray
   input once before the parser pipeline so validation sees one bounded value.

## Implementation

1. Freeze the complete semantic source at
   `changes/st-0204/contracts/runtime-config.v1.yaml`.
2. Implement strict immutable Pydantic models and a bounded environment parser
   under `python/raos/config/` without adding a configuration dependency.
3. Generate the language-neutral JSON Schema from the typed model and build a
   content-addressed Story manifest pinned to canonical inputs and ST-0203.
   Fail closed before rendering unless Python 3.14.6, Pydantic 2.13.4,
   pydantic-core 2.46.4, PyYAML 6.0.3, and uv 0.12.1 match the reviewed
   contract; include the lock/config files and shared manifest builder in the
   source closure.
4. Return diagnostics through an exact public allowlist containing only
   environment, service/log metadata, sorted reference aliases, and count.
5. Add positive, negative, parser-bound, schema, generation, and privacy tests
   in an isolated Story suite.
6. Wire generator checks into repository policy and the suite into the
   existing offline Unit boundary; add no provider or staging job.

## Completion boundary

Local deterministic execution can establish an implementation candidate. It
cannot establish provider Secret retrieval, workload identity, rotation,
staging privacy validation, Security Owner approval, release, production, or
formal TST-005/TST-031 status.
