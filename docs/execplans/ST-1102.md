# ST-1102 — Article workspace UI local completion

## 1. Story and outcome

- Story: `ST-1102`
- Objective: integrate the Content AST, AI proposal diff, Claim/Evidence,
  Comparison, and SEO views in one Article Workspace.
- Acceptance boundary: deterministically model stale `If-Match` conflicts and
  an unsaved-changes navigation guard without granting a save, navigation,
  approval, publication, or Production effect.
- Non-goals: route registration, browser rendering, OIDC/MFA, backend
  authorization, persistence, provider access, publication, staging, release,
  and Production operation.

## 2. Context read

- Canonical integration design, decisions, open decisions, Story backlog, UI
  design, screen/component/workflow catalogs, accessibility checklist,
  security design/control catalog and role matrix, and TST-022/TST-024.
- Cumulative Admin OpenAPI operations `ED-007`, `ED-010`, `ED-011`, `ED-023`,
  `ED-024`, and the shared `ETag`/`If-Match`/412/428 conventions.
- ST-0806 V2 contract, completion record, generated plan and exact recorded
  synthetic fixture.
- ST-1101 serializable, route guard, AppShell, DataTable, form, and dialog
  headless foundations.
- Existing ST-1102 V1 metadata candidate and focused tests.

Open Decisions do not attach to ST-1102. `OD-010` still disables the ST-1101
authentication transport. SEO data is not supplied by either declared Story
dependency, so the SEO pane must remain explicitly partial/unavailable rather
than inventing an ST-0807 result.

## 3. Invariants

- The existing V1 TypeScript source remains byte-identical.
- ST-0806 output remains a human-editable proposal; it is not adopted or
  persisted by this Story.
- A stale or absent `If-Match` never permits overwrite.
- Unsaved state can block a modeled navigation decision but cannot perform or
  intercept navigation in this headless package.
- Catalog roles are display metadata only; backend authorization remains
  mandatory and unavailable here.
- No raw prompt, source body, review body, arbitrary URL, finance/affiliate
  economics, credential, personal data, provider call, or public projection is
  accepted or emitted.
- Missing SEO data is `UNAVAILABLE_DEPENDENCY`, never an empty successful
  value.

## 4. Proposed design

- Add a versioned Story-local contract for a disabled, recorded/synthetic V2
  projection.
- Add an owner generator which validates exact source hashes, recomputes the
  ST-0806 typed AST diff and Claim coverage from its recorded fixture, emits a
  minimized UI projection, a TypeScript fixture wrapper, and a complete
  manifest using the hardened atomic writer.
- Add an additive TypeScript V2 model that validates the generated projection,
  maps each canonical EDT screen to its owned pane, and exposes pure ETag and
  unsaved-guard evaluators.
- Keep routes/rendering/effects disabled and all authority fields false.
- No migration, API handler, event, job, transaction, or rollback operation is
  introduced.

## 8. Risks and decisions

- Risk: confusing synthetic data with live editorial state. Mitigation: every
  projection is marked recorded/synthetic DEV/CI-only and production
  ineligible.
- Risk: interpreting a matched ETag as save authority. Mitigation: the result
  is `MATCHED_NO_COMMAND`; dispatch, persistence, and mutation remain false.
- Risk: inventing SEO output. Mitigation: retain only its typed reference and
  title source while canonical/robots/JSON-LD remain unavailable.
- Provisional implementation detail: structural AST block metadata is enough
  for this headless local projection; actual editable controls and DOM behavior
  remain a later browser/runtime boundary.
