# ST-0003 ExecPlan — Apply AI governance canonical revision

## 1. Story and outcome

- Story ID: `ST-0003`
- Epic: `EPIC-00`
- Requirement: `FR-018`
- Canonical decision: `INT-DEC-004`
- Outcome: consume the hash-pinned ST-0002 v0.2 candidate and the immutable
  RAOS-AI-001 package to produce a self-contained v0.3 revision. The revision
  makes AI tasks, prompts, routes, evaluation datasets/runs, human evaluation,
  judge calibration, and release decisions first-class DB/API/event
  contracts, and supplies deterministic JSON Schema type artifacts.

Explicit non-goals:

- installing the final contract repository or language clients
  (`ST-0104`, `ST-0105`);
- implementing the migration runner/history/lock ABI (`ST-0301`);
- installing all domain schemas, grants, or repositories
  (`ST-0304`, `ST-0306`, `ST-0308`);
- implementing the AI registry loader, provider adapter, router, orchestration,
  validators, or evaluation runtime (`ST-0701`–`ST-0708`);
- changing a production database, invoking a provider, publishing content, or
  approving an AI release.

No Open Decision is attached to ST-0003. Safe interpretations:

- v0.3 layers on v0.2; regenerating from the v0.1 API package would erase the
  accepted Job-state correction and is forbidden.
- The API proposal supplies operation identifiers and paths but not complete
  schemas or event payloads. The implementation uses strict, internal-only
  resource types and minimal lifecycle events that contain identifiers,
  versions, hashes, decisions, and audit metadata only—never prompt bodies,
  source packets, raw model output, secrets, finance data, or review bodies.
- Legacy `ai.ai_job.BLOCKED` is terminal in the predecessor contract, while
  `AWAITING_HUMAN` is non-terminal in the adopted lifecycle. The migration
  therefore does not guess a mapping: Contract refuses unresolved `BLOCKED`
  rows until an operator classifies each row from evidence. Legacy `FAILED`
  maps losslessly to `FAILED_TERMINAL`; legacy `PENDING` maps to `REQUESTED`.
- Legacy prompt `REJECTED` is likewise not silently collapsed into `RETIRED`.
  Contract refuses unresolved rows until an operator records the intended
  terminal classification. Existing route states are a subset of the accepted
  route lifecycle.
- “generated types” means versioned, strict JSON Schema resource/event/task
  types in this contract revision. Python/TypeScript generation remains owned
  by ST-0105.

## 3. Invariants

- AI output remains a proposal and cannot approve, publish, clear blockers,
  alter deterministic scores, mutate authoritative state, or select itself for
  release.
- Every Canary and Active approval is a fresh append-only signature bundle
  from two distinct ACTIVE USER principals; neither approver may be the Prompt
  author, and Active must use a new manifest and a new signature artifact.
- Every executable AI job binds task, prompt, output schema, route, policy,
  release decision, input manifest hash, requested/resolved model, token, and
  cost provenance without storing secrets.
- Every provider-backed Evaluation Case Result binds one immutable AI Attempt,
  its exact immutable input artifact/hash, and—only for successful calls—its
  exact immutable output artifact/hash. Refusal and terminal-failure results
  require the corresponding failed validation evidence; metric, grader,
  human-review, and expected-disposition coverage is complete and canonical.
- Every canonical required split contains at least one Case. Blocking metrics
  pass both their split-wide and every represented Case-category aggregate for
  HOLDOUT, ADVERSARIAL, and REGRESSION; ratio aggregates sum integer
  numerators/denominators and p95 aggregates use a scope-local percentile.
- Every Case records an exact eight-code zero-tolerance map bound to immutable
  grader evidence. Its failure count is generated, and the six metric-backed
  safety codes require their canonical metric observation on every Case.
- A candidate with a current `APPROVED_ACTIVE` Champion binds a distinct,
  completed Champion-config baseline rerun on the candidate Suite/Dataset.
  Regression compares exact Case/metric/grader/threshold/judge pairs overall
  and per category; the baseline may be omitted only when the task currently
  has no `APPROVED_ACTIVE` Champion, including after all prior releases are
  explicitly revoked.
- Once an Evaluation Run leaves `PLANNED`, the evaluated Task, Prompt, Route,
  Output Schema, resolved Model, and Policy Bundle identity and content
  snapshots are permanently frozen. Worker roles cannot mutate those
  authority tables or policy decision state.
- Current canonical latency/cost p95 observations are report-only and therefore
  carry null threshold/operator/pass state. A future versioned suite may add
  either code to `required_metrics`; that branch requires exact non-null
  threshold/pass provenance and applies the scope-local p95 blocking gate.
- Policy Bundle membership is append-only and accepts only ACTIVE Rule
  Versions while the parent is DRAFT. Activation requires at least one bound
  Rule. Rule semantic content and hashes freeze after DRAFT; legal retirement
  remains available only when no ACTIVE Bundle references that Rule Version.
- Every release decision directly binds task, prompt, output schema, route,
  resolved model, policy bundle, dataset, evaluation run, application code
  SHA, exact model-judge calibration when used, rollback strategy/evidence,
  manifest hash, and phase-specific human approval evidence. Canary is a
  non-terminal state and Active cannot skip it or reuse its signature.
- Canary timestamps/transaction identifiers are server-owned and immutable.
  Critical-task Canary is capped at one percent and the route cap, and a task
  may have only one `APPROVED_CANARY` at a time under task-level serialization.
  Rollback targets are same-task prior Active decisions whose six referenced
  components remain Active, and a live dependent prevents target/component
  revocation or lifecycle departure.
- Source packets and merchant content remain untrusted data. Tools, browsing,
  network access, review bodies, affiliate economics, hidden instructions, and
  unapproved content remain forbidden AI inputs.
- AI governance resources and events are internal/restricted. Public OpenAPI
  remains byte-identical to the immutable v0.1 public contract, and the public
  database role receives no AI schema/table access.
- Unknown fields are rejected at API, event, task-output, and evaluation trust
  boundaries.
- Existing v0.2 Job states, schemas, and wire contracts remain intact.
- Wilson lower bounds and pairwise win/tie/loss confidence intervals are
  required report evidence, not substitutes for DB point-estimate gates.
  Non-category multi-value slices are reporting-only; canonical latency/cost
  p95 remains reporting-only until a versioned suite declares a threshold,
  but both raw latency and cost observations remain mandatory for every Case.
- Proposal-only SQL/YAML is retained as provenance and never executed directly.
- Database changes use bounded Expand–Migrate–Contract checkpoints; validation
  does not retain metadata locks across table scans.

## 4. Proposed design

### Modules and ownership

- `changes/st-0003/database/` contains formal versioned SQL payloads and
  forward-recovery guidance for the future ST-0301 runner.
- `changes/st-0003/contracts/` is a generated self-contained v0.3 candidate.
  It starts from verified ST-0002 artifacts, preserves unchanged schemas, and
  adds RAOS-AI-001 catalogs, prompts, task/evaluation schemas, governance
  resource schemas, and internal lifecycle event schemas.
- `scripts/build_st0003_revision.py` verifies every predecessor artifact and
  immutable input hash, renders in sibling staging, and installs only an owned
  complete generated tree.
- `tests/st0003/` owns deterministic generation, compatibility, reference,
  public-isolation, API contract, schema, and PostgreSQL migration checks.

### Data and transaction boundaries

The SQL payload is split into independently recorded checkpoints:

1. Expand: add nullable reproducibility/concurrency fields, side-by-side
   permissive constraints/FKs, and empty governance tables.
2. Expand validation/index: validate after releasing metadata locks, create
   exact concurrent indexes, and verify their definitions.
3. Migrate batch: process at most 1,000 legacy rows total per transaction,
   including only lossless AI Job lifecycle mappings and deterministic
   metadata backfill. Ambiguous `BLOCKED`/`REJECTED` rows remain visible for
   operator classification. Repeat until the reported automatic backlog is
   zero.
4. Contract prepare: assert the backlog is empty, install NOT VALID required
   constraints that immediately reject new legacy writes, and set safe
   defaults.
5. Contract validate/finalize: validate without retaining an
   `ACCESS EXCLUSIVE` lock, then use a separate short transaction for NOT NULL,
   canonical constraints, defaults, and predecessor constraint removal.
6. Guarded downgrade: freeze relevant writers, refuse any non-empty governance
   table or meaningful non-baseline metadata, reverse only lossless legacy
   states, explicitly remove the circular release-approval bindings without
   `CASCADE`, and prove restoration of the post-ST-0002 shape and data.

### API, event, and type changes

- Keep AI-001–AI-008 operation authorization, idempotency, concurrency, and
  success semantics unchanged. AI Job schemas may receive additive optional
  lifecycle metadata, but the legacy cancel operation cannot gain a required
  `If-Match` in place because the adopted compatibility policy classifies that
  as breaking. A hardened cancel command requires a versioned successor.
- Add AI-101–AI-115 only to Admin OpenAPI, with OIDC scopes, RFC 9457 errors,
  Idempotency-Key on commands, If-Match/ETag on mutable state transitions, and
  internal/restricted classifications.
- Keep existing events and add only the minimum explicitly consumed lifecycle
  events: `evaluation_completed.v2`, `release_decision_approved.v1`, and
  `release_decision_revoked.v1`. Dataset lock and evaluation-run request remain
  HTTP commands plus audit actions until a non-HTTP consumer is specified.
- Generate strict schemas for the canonical governance resources and copy all
  12 task-output plus 2 evaluation schemas byte-for-byte from RAOS-AI-001.
- Copy the 12 hash-bound prompt templates and relevant machine-readable AI
  catalogs; omit bootstrap cases and review-contamination fixtures from the
  production contract bundle.

### Failure and rollback behavior

- Any predecessor/hash/ref/schema mismatch aborts before replacing committed
  generated output.
- A failed staged install restores the previous complete owned tree.
- Contract refuses ambiguous legacy state rows and remaining required-metadata
  gaps.
- Downgrade refuses lossy state mappings, non-empty governance tables,
  meaningful release/policy/hash fields, or non-default governance metadata.
- Forward recovery is the default after Contract begins.

### Security, privacy, and accessibility impact

- This story adds no UI.
- Public API/read model remains unchanged and contains no AI resource, prompt,
  route, dataset, evaluation, release, raw artifact, or internal event.
- Schemas expose only metadata/hash/identifier fields. Prompt text, provider
  secrets, raw input/output, source packets, holdout content, and personal data
  are not API/event fields.
- No external connector, provider call, credential, production write, or
  publication action is used.

## 8. Risks and decisions

- The proposals omit lifecycle constraint migration, concurrency versions,
  complete resource schemas, and event payloads. The revision fills these gaps
  with fail-closed types and explicit compatibility tests.
- `BLOCKED` and `REJECTED` have no meaning-preserving automatic mapping into
  the adopted state machines. Keeping them visible and blocking Contract is an
  intentional operator checkpoint, not a stalled batch.
- Cross-row phase approval cannot be expressed by a simple CHECK constraint.
  The DB therefore validates two distinct ACTIVE USER principals, fixed roles,
  Prompt-author separation, exact manifest and immutable signature hashes,
  canary evidence, and transaction ordering in serialized triggers; the later
  application story must additionally bind the authenticated caller to the
  recorded principal and authorization policy.
- Existing AI attempts can deterministically recover requested/resolved model
  identifiers from their referenced model definition. Non-derivable input
  manifest/release metadata remains nullable for legacy rows and is required by
  the new command contract.
- Language code generation before ST-0104/ST-0105 would cross story ownership,
  so this story stops at strict portable JSON Schema types.
