- Canonical Story: `ST-0605`, ClaimとFactのLink/Coverage (`FR-007`).
- Required suites: `TST-020`, `TST-021`; their formal execution status remains
  `NOT_EXECUTED`.
- Local scope: pure evaluator, read-only snapshot port, recorded ENV-DEV/CI
  adapter, internal append-only report port, deterministic fixture/generator,
  focused tests, and local evidence records.
- Hard stops: no publication, credential, provider/live call, database write,
  staging/release/Production action, or inferred policy/persistence/AI mapping.

## Implementation slices

1. Add strict ST-0605 policy vocabularies and hash-bound snapshot records.
2. Evaluate exact closure of Claims, proofs, Facts, links, Sources, snapshots,
   identity, conflicts, citations, and owner attestations without mutation or
   I/O.
3. Count only valid `SUPPORTS`; apply 100%/95% integer thresholds and
   zero-denominator `UNEVALUABLE` behavior.
4. Require owner Story/contract/version/hash receipts for Claim inventory,
   Article/Packet, Packet membership, Fact validation, conflict closure,
   Product/Variant identity, and type-specific validation. Missing receipts
   remain `UNEVALUABLE`; recorded-synthetic decision digests detect corruption
   but do not authenticate an owner, and ST-0803/ST-0804 algorithms are not
   moved here.
5. Bind evaluator version, evaluation time, the complete evaluation input hash,
   coherent coverage fields, and report hash. Resolve the Article Version from
   the trusted preloaded reader and re-evaluate that exact snapshot before
   append. Preserve constructor-time full-input and append-history values as
   immutable digest/byte anchors instead of caller-owned object aliases; the
   pure evaluator itself grants no authority.
6. Add read-only application evaluation and process-local append-only record
   services with a recorded adapter restricted to ENV-DEV/CI.
7. Generate and hash-bind a synthetic passing fixture, every repository-backed
   module in the fresh runtime import closure, and the exact locked generation/
   verification toolchain. Use transactional replacement/rollback for ordinary
   exceptions and asynchronous Python interruptions before commit. Retry
   post-commit cleanup and report persistent residue with a closed diagnostic;
   power loss is excluded.
8. Test positive, boundary, negative, prohibited-source, security, drift, and
   non-authority behavior; then record local completion without changing
   Canonical status.

## Completion boundary

Local completion requires owner `--check`, focused pytest, compile/import,
Ruff, strict mypy, focused secret scan, and `git diff --check` to pass.  It does
not satisfy formal TST-020/TST-021, approve a Source Packet in a live system,
authorize publication, or establish staging/release/Production readiness.
