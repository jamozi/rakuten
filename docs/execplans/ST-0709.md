# ST-0709 — AI governance admin workspace local implementation

## 1. Story and outcome

- Story: `ST-0709`
- Objective: provide a deterministic local `GOV-001` projection that displays
  Task, Prompt, Route, Evaluation, Release, and Cost metadata.
- Acceptance boundary: no direct activation without human approval.
- Outcome: a source-bound, recorded/headless V2 workspace model and generated
  fixture that are locally executable without registering an Admin route or
  granting any operational authority.
- Non-goals: React/DOM rendering, OIDC, server authorization, live provider
  access, credentials, persistence, route mutation, activation, approval,
  publication, release, staging, or Production writes.

## 3. Invariants

- Existing ST-0709 V1 source and focused test bytes remain unchanged.
- Unknown or unavailable values remain explicit and are never rewritten to
  zero, active, approved, release-ready, or Production-eligible.
- Catalog `enabled` metadata never becomes runtime activation authority.
- No raw prompt, source packet, provider response, secret, personal data,
  Rakuten review body, or finance/recommendation input is projected.
- Every visible status has text, code, and icon metadata and is not color-only.
- All public values are detached, deeply frozen, strict JSON data.
- The UI model exposes no callback, effect, provider, persistence, approval,
  activation, publication, or release capability.

## 4. Proposed design

- Add a V2 owner contract describing exact sources, projection rules, safety
  boundary, output paths, and formal non-execution status.
- Add a Python owner generator that verifies content hashes and semantics,
  executes the exact recorded ST-0707/ST-0708 validation paths, derives closed
  display rows, and atomically emits canonical JSON, a TypeScript JSON binding,
  and a runtime manifest.
- Add a browser-neutral TypeScript V2 loader/validator and workspace factory.
  It validates complete generated candidate shape, semantic table metadata,
  cross-section identities, explicit unavailability, and all authority flags.
- Export the V2 surface additively; retain the V1 public surface unchanged.
- Add focused source, model, generation, hostile-input, authority, integrity,
  and dependency-regression tests.

No migration, API revision, route registration, or runtime service is added.
The accepted AI governance SQL/API overlays remain implementation inputs for
their own integration Stories rather than being applied by this UI Story.

## 8. Risks and decisions

- Risk: task registry candidate `enabled` fields could be mistaken for active
  runtime state. Mitigation: project them only as catalog metadata and pair
  every route with `NOT_AUTHORIZED` activation/release states.
- Risk: configured task cost ceilings could be mistaken for observed spend.
  Mitigation: label them as candidate limits; observed cost remains unavailable.
- Risk: a display-only role list could be mistaken for authorization.
  Mitigation: keep route registration disabled and all authorization flags false.
- Provisional local detail: ST-0708 is included as the nearest recorded release
  proposal available at the selected base; it remains authority `NONE` and is
  not elevated to a Canonical direct dependency.
