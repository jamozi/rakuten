# Selected official-source replay

`validate_selected_official_sources(repository_root, evidence_root, article_ids,
now)` in `python/raos/application/editorial/verified_incremental_sources_v1.py`
validates existing captures for selected articles only. It does not capture,
download, create directories, modify sources, read credentials, mark owner
attestations, or grant publication authority.

`repository_root` supplies the current tracked registry and locator contract.
`evidence_root` explicitly supplies the repository-style root containing
`.secrets/st1704-self-hosted-editorial-pilot/sources/`. It need not equal the
contract checkout. This is official-source evidence; it does not change the
separate rule that Rakuten credentials/provider responses remain in the saved
owner checkout. Never copy private captures into tracked fixtures or logs.

`article_ids` uses the source registry's identities, not arbitrary URL slugs.
The first five articles use the `PILOT_ARTICLE_IDENTITIES` article IDs (for example,
`st1703-first-suitcase-comparison`); the latter five currently use their slugs.
Map from a reviewed publication target through that registry; do not guess an ID
or silently expand an unknown selection to the full portfolio.

## Validation

- Load the existing exact capture plan, which cross-validates the complete
  descriptive registry and locator contract. Only selected article source refs
  require stored captures; unrelated articles' missing evidence is irrelevant.
- Derive each selected article's claim/source map from its registry packet.
  A shared source can have locators for other articles; that does not add those
  articles' claims to the selected article's output map.
- Replay each selected capture through the existing safe private reader. That
  reader validates response/body hashes, fragment hashes, each fragment's unique
  occurrence in the raw body, and metadata stability.
- Additionally require the exact current official URL, media type, ordered
  locator claim/statement/fragment bindings, any fixed PDF body digest, observed
  date floor, and capture age **strictly below 24 hours**, never in the future.
- Hash raw metadata bytes, retain the verified body digest and response digest,
  and bind current contract file hashes. Reopen every successful capture after
  inspecting the selected set. Re-read contract files before completion.
- No date or digest is refreshed merely because replay ran again. Capture expiry
  is the original retrieval time plus 24 hours; final release expiry must not
  exceed the earliest selected capture expiry.

## Output

`SelectedOfficialSourcesV1` exposes `status` (`VERIFIED` or `BLOCKED`),
`article_claim_sources`, `article_source_refs`, per-source receipt/file/body
hashes, `source_receipt_sha256`, `expires_at`, and `require_complete()`.
`to_document()` is JSON serializable and contains no URLs, source excerpts,
filesystem locations or owner-attested claims.

Missing, unsafe, pending, stale, changed or mismatched captures appear as stable
per-source issue codes associated with affected selected article IDs. Other
valid selected receipts remain available for diagnosis, but `require_complete()`
rejects an incomplete selected set, and its `expires_at` is null. Invalid selection
or changing/malformed current contracts raises `SelectedOfficialSourcesFailure`.

The receipt digest is SHA-256 of the domain helper's canonical JSON bytes of
`SelectedOfficialSourceReceiptV1.to_document()` (without an added newline).
`evidence_file_sha256` hashes the exact stored file bytes, including its existing
formatting. These are separate identities and must not be interchanged.

## Deliberate boundaries

The existing trusted evidence domain currently accepts HTML/PDF, not JavaScript.
JavaScript targets return `MEDIA_TYPE_UNSUPPORTED_BY_READER`; relabelling them as
HTML is forbidden. PDF captures must pass the existing exact-body replay reader;
reviewed-page metadata does not excuse a missing raw-body fragment. Unsupported
reader cases need a separately tested contract change, not a silent bypass.

Article packet source refs do not include every site's policy source by default.
Changing shared policy pages still needs that policy's source/operational checks.
Source replay also does not prove that the article's prose means what its source
says, does not run product safety searches, and does not verify commercial media
or CTA identity. Those remain mandatory independently bound release/audit checks.

Tests use real private readers over synthetic files; no live capture or real
completed editorial review is generated by the test suite.
